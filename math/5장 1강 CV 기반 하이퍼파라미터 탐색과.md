## 하이퍼파라미터 후보는 어떤 기준으로 비교해야 할까?

모델이 데이터에서 학습하는 가중치·분할 기준 같은 값을 **파라미터**<br>
y=wx+b, w 하고 b가 파라미터이다

트리 수, 최대 깊이처럼 학습 전에 사람이 정하는 설정을 하이퍼파라미터<br>

```python
RandomForestClassifier(
    n_estimators=100,   # 트리수
    max_depth=5         # 최대 깊이
)
```

하이퍼파라미터 탐색
= 좋은 설정을 찾는 과정

방법 1: Grid Search
→ 정해둔 조합을 전부 확인

방법 2: Random Search
→ 여러 조합 중 일부를 랜덤하게 뽑아서 확인


이번 강의에서는 각 후보를 같은 4-fold CV로 평가.
Grid Search와 Random Search를 탐색법당 12개 후보라는 같은 평가 횟수로 실행한 뒤, 
CV 평균과 fold 간 변동을 우선해 후보를 고릅니다.<br>
값이 같으면 적은 트리 수와 얕은 깊이를 동률 해소 기준으로 사용.


CV의 점수 = 각 Validation fold에서 계산한 성능 평가 지표 값
예: AP, F1, Accuracy, ROC-AUC 등
CV 평균 = 각 fold에서 나온 평가 점수들의 평균
fold 간 변동 = 각 fold의 평가 점수들이 얼마나 차이 나는지
보통 표준편차(std) 로 표현
작을수록 fold마다 성능이 비슷해서 더 안정적


test는 이 모든 선택이 끝난 뒤 한 번만 확인.

## 검토 라우터

검토 라우터는 AI가 만든 답변을 보고, 그 답변을 사람 검토 필요 (needs_review=1)와 자동 처리 후보 (needs_review=0) 2개 중 자동으로 나누는 분류 모델

14개의 익명 수치 특성을 입력으로 사용해서 모델이 점수를 내어 이 답변이 사람 검토가 필요한지 판단한다.

threshold는 needs_review=1과 needs_review=0을 나누는 기준값이고, 
AP는 그 기준으로 0/1을 나눈 결과가 아니라 needs_review=1 점수의 순위가 얼마나 잘 정렬되었는지를 평가하는 지표다.


### 탐색보다 먼저 비교 계약과 선정규칙을 고정한다

먼저 test를 떼어 봉인 후 결과를 보기 전에 비교 조건을 고정
그다음 개발 데이터 안에서 후보를 비교하고 하나를 고정한 뒤, 
개발 데이터 전체로 다시 학습해 test를 한 번 평가.

## 1. CV는 탐색 안에서 후보를 평가합니다

후보 하나를 한 번의 validation 분할에서만 평가하면 그 분할에 우연히 잘 맞는 설정을 고를 수 있다. <br>
그래서 CV는 개발 데이터를 여러 fold로 나누고, 후보마다 같은 fold를 반복 사용해 평균과 변동을 확인

**이때 중요한 것은 탐색법보다 비교 조건을 먼저 정하는 것**


| 비교 항목 | 이번 실습의 고정값 | 고정하는 이유 |
| --- | --- | --- |
| 데이터 | 같은 `X_dev`, `y_dev` | 데이터 차이를 설정 차이로 오해하지 않기 위해 |
| CV | 같은 4개 Stratified fold | 분할 운을 탐색법 차이로 오해하지 않기 위해 |
| 모델·지표 | Random Forest·AP | 모든 후보가 같은 질문에 답하게 하기 위해 |
| 탐색 경계·평가 횟수 | 같은 최소·최대 경계, 탐색법당 12개 후보 | 더 많은 기회를 성능 차이로 오해하지 않기 위해 |
| seed·test 시점 | 42·후보 고정 뒤 1회 | Random 후보를 재현하고 test 선택 편향을 막기 위해 |


**결과를 보기 전에 함께 고정하는 후보 선정 규칙**

1. 전체 후보에서 가장 높은 CV 평균 AP를 찾습니다.
2. 최고 평균에서 AP 절대 차이 `0.01` 이내인 후보만 남깁니다.
3. 남은 후보 중 fold 표준편차가 가장 작은 후보를 고릅니다.
4. 표준편차가 같으면 트리 수 → 깊이 → 탐색법 이름 순서로 동률을 풉니다.

`0.01`은 최고 점수의 1%가 아니라 AP 1 percentage point이며, 통계적 유의성 기준이 아닌 교육용 업무 기준입니다. 코드에서도 `MEAN_TOLERANCE`와 `SELECTION_ORDER`를 탐색 전에 정의한다.

Grid와 Random은 같은 최소·최대 경계와 같은 후보 평가 횟수를 사용하지만, 실제로 확인하는 좌표는 서로 다릅니다. 

같은 CV fit 수라도 후보의 트리 수와 깊이에 따라 실제 시간·메모리는 달라질 수 있다. <br>
따라서 이번 한 번의 최고 점수만으로 “어느 탐색법이 항상 더 좋다”고 결론 내리지 않는다.

## 2. Grid Search와 Random Search를 같은 후보 평가 횟수로 비교합니다

**GridSearchCV**

미리 적은 이산 조합을 빠짐없이 평가합니다. 공간이 작고 살펴볼 값이 분명할 때 이해하기 쉽습니다.

**RandomizedSearchCV**

더 넓은 후보 목록이나 분포에서 `n_iter`개 조합을 뽑습니다. 정해진 후보 수 예산으로 다양한 좌표를 보고 싶을 때 유용합니다.
