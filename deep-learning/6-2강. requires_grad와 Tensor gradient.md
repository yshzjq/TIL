## 1. 이번에 배울것

gradient가 실제 Tensor 안에서 어떻게 관리되는지 확인

PyTorch에서 Tensor는 단순한 숫자 배열이 아니다. <br>
필요하면 연산 기록을 추적하고, `backward()` 이후 gradient를 저장할 수 있습니다. <br>
이 기능을 켜는 핵심 옵션이 `requires_grad=True`이다.

모델이 학습되는 이유는 weight와 bias 같은 파라미터가 gradient를 받고, optimizer가 그 gradient를 이용해 값을 업데이트하기 때문이다.

## 2. `requires_grad`는 무엇인가요?

`requires_grad=True`는 이 Tensor와 관련된 연산을 추적하겠다는 뜻

```python
import torch

# gradient를 추적하지 않는 일반 Tensor입니다.
a = torch.tensor(2.0)

# gradient를 추적하는 Tensor입니다.
w = torch.tensor(3.0, requires_grad=True)

print("a.requires_grad:", a.requires_grad)
print("w.requires_grad:", w.requires_grad)
```

출력

```
a.requires_grad: False
w.requires_grad: True
```

`requires_grad=True`인 Tensor가 연산에 참여하면, PyTorch는 그 연산 기록을 계산 그래프로 남긴다

```python
x = torch.tensor(2.0)
w = torch.tensor(3.0, requires_grad=True)

# w가 requires_grad=True이므로 y도 gradient 추적 대상이 됩니다.
y = x * w
loss = y ** 2

print("y.requires_grad:", y.requires_grad)
print("loss.requires_grad:", loss.requires_grad)
print("loss.grad_fn:", loss.grad_fn)

# 출력
#y.requires_grad: True
#loss.requires_grad: True
#loss.grad_fn: <PowBackward0 object at 0x7ab296b6e380>
```

## 3. leaf tensor와 non-leaf tensor

PyTorch Autograd를 사용할 때 자주 나오는 개념이 **leaf tensor**입니다.

Autograd에서 `requires_grad=True`인 leaf tensor는 다른 연산의 결과로 만들어지지 않은 계산 그래프의 시작 Tensor다.

엄밀히 말하면 `requires_grad=False`인 Tensor는 관례상 leaf로 취급,<br>
```python
import torch

# 직접 만든 Tensor입니다.
w = torch.tensor(3.0, requires_grad=True)

# 연산 결과로 만들어진 Tensor입니다.
y = w * 2
loss = y ** 2

print("w.is_leaf:", w.is_leaf)
print("y.is_leaf:", y.is_leaf)
print("loss.is_leaf:", loss.is_leaf)
```

출력

```
w.is_leaf: True
y.is_leaf: False
loss.is_leaf: False
```

여기서 `w`는 직접 만든 Tensor이므로 leaf tensor다.<br>
`y`와 `loss`는 연산 결과로 만들어졌기 때문에 non-leaf tensor입다.

모델의 weight와 bias는 보통 leaf tensor이고, layer를 통과해 만들어진 중간 activation은 non-leaf tensor다

## 4. `.grad`는 어디에 저장되나

`backward()`를 호출하면 gradient는 보통 leaf tensor의 `.grad`에 저장된다

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
y = w * 2

loss = y ** 2

print("backward 전 w.grad:", w.grad)

loss.backward()

print("backward 후 w.grad:", w.grad)
print("y.grad:", y.grad)
```

`w.grad`에는 값이 저장되지만, `y.grad`는 기본적으로 `None`이다. <br>
`y`는 중간 계산 결과인 non-leaf tensor이기 때문이다

PyTorch 버전에 따라 non-leaf의 `.grad`를 읽을 때 저장되지 않는다는 경고도 함께 표시될 수 있다

중간 Tensor의 gradient를 꼭 보고 싶다면 `retain_grad()`를 사용하면된다

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
y = w * 2

# non-leaf tensor인 y의 gradient도 저장하고 싶다고 명시합니다.
y.retain_grad()

loss = y ** 2
loss.backward()

print("w.grad:", w.grad)
print("y.grad:", y.grad)

# 출력
# w.grad: tensor(24.)
# y.grad: tensor(12.)
```

## 5. `nn.Linear` 파라미터의 gradient 확인하기

실전에서는 Tensor를 직접 만들기보다 `nn.Linear` 같은 layer를 사용한다.<br>
`nn.Linear`의 weight와 bias는 학습 가능한 파라미터다.

```python
import torch
import torch.nn as nn

# 입력 feature 3개를 출력 1개로 바꾸는 선형층입니다.
model = nn.Linear(3, 1)

# 더미 입력과 정답입니다.
x = torch.randn(4, 3)
y = torch.randn(4, 1)

criterion = nn.MSELoss()

# forward
pred = model(x)
loss = criterion(pred, y)

# backward 전에는 gradient가 아직 없습니다.
print("before backward")
print("weight.grad:", model.weight.grad)
print("bias.grad:", model.bias.grad)

# backward
loss.backward()

# backward 후에는 gradient가 저장됩니다.
print("after backward")
print("weight.grad shape:", model.weight.grad.shape)
print("bias.grad shape:", model.bias.grad.shape)

# 출력
# before backward
# weight.grad: None
# bias.grad: None
# after backward
# weight.grad shape: torch.Size([1, 3])
# bias.grad shape: torch.Size([1])
```
`model.weight.grad.shape`는 `model.weight.shape`와 같습니다. 

gradient는 각 파라미터와 같은 모양으로 저장된다

```python
print("weight shape:", model.weight.shape)
print("weight grad shape:", model.weight.grad.shape)

print("bias shape:", model.bias.shape)
print("bias grad shape:", model.bias.grad.shape)
```

파라미터의 gradient shape는 파라미터 shape와 같다

## 6. `torch.no_grad()`로 gradient 추적 끄기

평가나 예측만 할 때는 gradient를 계산할 필요가 없습니다. 이때 `torch.no_grad()`를 사용한다

```python
import torch
import torch.nn as nn

model = nn.Linear(3, 1)
x = torch.randn(4, 3)

# 일반 forward는 gradient 추적이 켜질 수 있다.
pred = model(x)
print("pred.requires_grad:", pred.requires_grad)

# no_grad 안에서는 gradient 추적을 하지 않는다.
with torch.no_grad():
    pred_eval = model(x)

print("pred_eval.requires_grad:", pred_eval.requires_grad)
```

`torch.no_grad()`는 주로 validation loop나 inference code에서 사용한다. <br>
gradient 추적을 끄면 메모리 사용량을 줄이고 평가 코드를 더 안전하게 만들 수 있다.

## 7. `detach()`: 값은 사용하되 이 경로로는 학습하지 않기

`detach()`는 Tensor의 숫자 값은 그대로 두면서, 그 Tensor를 현재 계산 그래프에서 분리한다

### 7-1. 왜 계산 그래프를 끊어야 하나요?

계산 그래프에 연결된 Tensor에는 숫자 값뿐 아니라, 그 값이 어떤 연산을 거쳐 만들어졌는지에 대한 연결 정보도 남아 있다.<br>
이 연결 정보가 있기 때문에 `backward()`가 loss에서 출발해 앞쪽 파라미터까지 gradient를 전달할 수 있다.

하지만 딥러닝 코드에서는 **값은 필요하지만 그 값을 통해 역전파할 필요는 없는 상황**이 있다.

- 예측 결과를 NumPy 배열로 바꾸어 분석하거나 시각화할 때
- `optimizer.step()` 전후의 파라미터 값을 비교하기 위해 현재 값을 보관할 때
- 중간 Tensor를 다른 계산에 사용하되, 그 계산의 gradient가 앞쪽 모델까지 전달되지 않게 할 때

이때 Tensor 자체를 버리는 것이 아니라, 값은 가져가고 backward 경로만 끊는 것이 detach()다.

```
일반 Tensor
값 사용 O + backward 연결 O

detach한 Tensor
값 사용 O + backward 연결 X
```

`detach()`는 값을 삭제하거나 0으로 만드는 기능이 아닙니다. <br>
**forward에서 사용할 숫자 값은 그대로이고, backward가 지나갈 길만 끊는다다.**

### 7-2. 값은 loss에 사용되지만 gradient는 전달되지 않을 수 있다

다음 예제에서는 하나의 중간값 `y`를 두 갈래로 사용한다. 
<br>`a` 경로는 계산 그래프에 그대로 연결하고, `b` 경로에는 `detach()`를 적용한다.

```python
import torch

# x는 gradient를 계산할 대상입니다.
x = torch.tensor(2.0, requires_grad=True)

# x를 사용해 중간값 y를 만듭니다.
y = x * 3

# a 경로는 y와 계산 그래프로 연결되어 있습니다.
a = y * 4

# b 경로는 y의 값은 사용하지만,
# y 이전으로 gradient가 전달되지 않도록 끊습니다.
b = y.detach() * 5

# a와 b는 모두 loss의 숫자 값 계산에 사용됩니다.
loss = a + b

loss.backward()

print("y:", y)
print("a:", a)
print("b:", b)
print("loss:", loss)
print("x.grad:", x.grad)
```

forward에서 계산되는 값은 다음과 같다

```
y = 2 × 3 = 6
a = 6 × 4 = 24
b = 6 × 5 = 30
loss = 24 + 30 = 54
```

`b`에도 실제로 `y`의 값 6이 사용되었고, `b`의 값 30도 loss에 포함되었다. 
즉, `detach()`를 사용해도 forward 값 계산은 정상적으로 이루어졌다.

그러나 backward에서는 흐름이 다릅니다.

```
             ┌── ×4 ──> a ──┐
x ──×3──> y ┤               ├──> loss
             └─ detach ─×5─> b ──┘
                    ✂
```

a 경로의 gradient는 x까지 전달되지만, b 경로는 detach() 지점에서 끊긴다.<br>
x.grad에는 a 경로에서 온 gradient만 반영된다

```
a 경로의 gradient = 4 × 3 = 12
b 경로의 gradient = detach에서 차단
x.grad = 12
```

만약 다음처럼 `detach()`를 제거한다면 두 경로가 모두 연결된다

```python
b = y * 5
```

이 경우에는 다음처럼 두 경로의 영향이 모두 더해진다

```
x.grad = (4 + 5) × 3 = 27
```

### 7-3. `detach()`, `clone()`, `detach().clone()`의 차이

| 코드 | 계산 그래프 연결 | 별도 값 복사 | 의미 |
| --- | --- | --- | --- |
| `tensor.detach()` | 끊음 | 아님 | 값은 사용하지만 역전파 경로를 끊습니다. |
| `tensor.clone()` | 유지 | 함 | 값은 복사하지만 gradient 연결은 유지합니다. |
| `tensor.detach().clone()` | 끊음 | 함 | 계산 그래프와 분리된 독립적인 복사본을 만듭니다. |

`detach()`만 사용한 Tensor는 원본과 내부 저장 공간을 공유할 수 있다.<br>
따라서 업데이트 전 값을 안전하게 보관하는 비교용 스냅샷이 필요하다면 `detach().clone()`을 사용해야한다.

```
detach()
-> 이 복사본을 통해서는 역전파하지 않습니다.

clone()
-> 현재 값을 별도의 공간에 복사합니다.

detach().clone()
-> 학습과 연결되지 않은 독립적인 현재 값 보관
```

### 7-4. `detach()`와 `torch.no_grad()`의 차이

둘 다 gradient 추적과 관련되지만 적용 범위가 다르다.

| 구분 | `detach()` | `torch.no_grad()` |
| --- | --- | --- |
| 적용 대상 | 이미 만들어진 특정 Tensor | 블록 안에서 새로 수행되는 연산 전체 |
| 주요 상황 | 특정 지점에서만 gradient 경로를 끊을 때 | validation이나 inference 전체에서 gradient가 필요 없을 때 |

```python
# 특정 Tensor만 계산 그래프에서 분리한다
pred = model(x)
pred_detached = pred.detach()

# 이 블록 안의 연산 전체를 gradient 추적 없이 실행한다
with torch.no_grad():
    pred_eval = model(x)
```

평가나 추론처럼 구간 전체에서 gradient가 필요 없다면 `torch.no_grad()`가 자연스럽고,<br> 계산 도중 특정 Tensor의 연결만 끊고 싶다면 `detach()`를 사용한다


### 7-5. `detach()` 전후의 상태 확인하기

이제 가장 단순한 코드로 `detach()` 전후의 `requires_grad` 상태를 비교해본다

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
y = w * 2

# y_detached는 y와 값은 같지만 계산 그래프에서는 분리됩니다.
y_detached = y.detach()

print("y.requires_grad:", y.requires_grad)
print("y_detached.requires_grad:", y_detached.requires_grad)
```

`detach()`는 예측 결과를 NumPy로 변환하거나, 그래프 추적 없이 값을 로깅할 때 사용합니다.

```python
# 예측 결과를 기록하거나 시각화할 때 자주 쓰는 패턴입니다.
value_for_logging = y.detach().cpu().numpy()
print(value_for_logging)

# 출력
#y.requires_grad: True
#y_detached.requires_grad: False

```

학습해야 하는 loss 계산 중간에 실수로 `detach()`를 사용하면 gradient가 끊긴다.<br> 
초반에는 정말 필요한 경우가 아니면 loss 계산 전에 `detach()`를 사용하지 않는다

### 실수 1. `.grad`가 None인데 오류라고 생각하기

`backward()` 전에는 `.grad`가 None인 것이 정상

```python
model = nn.Linear(3, 1)
print(model.weight.grad)  # 아직 backward 전이므로 None입니다.
```

### 실수 2. 평가 코드에서 gradient를 계속 추적하기

```python
# 평가 때는 보통 이렇게 작성한다.
model.eval()
with torch.no_grad():
    pred = model(x)
```

### 실수 3. `detach()`를 loss 계산 전에 사용하기

```python
# 잘못된 예시입니다.
# pred를 detach하면 loss가 모델 파라미터와 연결되지 않을 수 있다.
example_x = torch.randn(4, 3)
example_y = torch.randn(4, 1)
detached_pred = model(example_x).detach()
detached_loss = criterion(detached_pred, example_y)
```
