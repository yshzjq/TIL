## 1. 이번에 배울것


딥러닝 실험에서는 모델 성능이 낮을 때 무작정 모델을 크게 만들면 안 된다.<br>
지금 문제가 과소적합인지, 과적합인지, 학습이 불안정한지 구분

train loss와 validation loss의 조합을 보고 현재 모델이 덜 배웠는지, 적당히 배웠는지, 지나치게 외웠는지 진단

## 2. Underfitting

Underfitting은 모델이 학습 데이터도 충분히 설명하지 못하는 상태
```
train loss 높음
valid loss 높음
train accuracy 낮음
valid accuracy 낮음
```

즉, 모델이 공부한 문제조차 잘 풀지 못하는 현상

Underfitting이 발생하는 흔한 원인

| 원인 | 설명 |
| --- | --- |
| 모델이 너무 단순함 | hidden size가 너무 작거나 layer 수가 부족할 수 있습니다. |
| 학습 epoch가 너무 적음 | 충분히 배울 시간이 부족할 수 있습니다. |
| learning rate가 너무 작음 | 파라미터가 너무 조금씩 바뀌어 학습이 느릴 수 있습니다. |
| 입력 feature가 부족함 | 데이터에서 문제를 풀 정보가 충분하지 않을 수 있습니다. |


**Overfitting과 distribution shift 구분**

train과 valid의 성능 차이가 크다고 해서 항상 Overfitting인 것은 아니다

train과 valid가 서로 다른 기간, 장소, 사람, 장비 등에서 수집되었다면

**두 데이터의 특성 자체가 다른 distribution shift**가 원인일 수도 있다.

예를 들어 train은 밝은 사진인데 valid는 어두운 사진 위주라면, 작은 모델에서도 valid 성능이 크게 떨어질 수 있다.<br> 이런 문제는 단순히 Dropout을 추가한다고 해결되지 않으므로 먼저 데이터가 어떻게 나뉘었는지 확인해야 한다


## 4. 좋은 fit은 어떤 상태인가요?

좋은 fit은 train 성능과 validation 성능이 모두 괜찮고, 둘 사이의 차이가 지나치게 크지 않은 상태다

```
train loss 낮음
valid loss 낮음
train accuracy 높음
valid accuracy 높음
train/valid gap이 너무 크지 않음
```

좋은 모델은 train 데이터만 잘 맞히는 모델이 아니라, validation 데이터에서도 안정적으로 동작하는 모델이다.

## 5. 학습 곡선으로 진단하기

표 기준으로 학습 상태를 빠르게 판단할 수 있다.

| train loss | valid loss | 진단 |
| --- | --- | --- |
| 높음 | 높음 | Underfitting 가능성 |
| 낮음 | 낮음 | Good fit 가능성 |
| 낮음 | 높음 | Overfitting 가능성 |
| 크게 흔들림 | 크게 흔들림 | 학습 불안정 가능성 |

단, 아래 threshold는 개념을 연습하기 위한 **heuristic 예시**일 뿐 보편적인 기준이 아니다.<br>
마지막 epoch 한 점만 보지 말고 여러 epoch의 추세, best epoch, 반복 실험의 변동을 함께 확인해야 한다.<br>
데이터셋 크기, metric, label 품질, class 불균형에 따라 적절한 기준도 달라집니다.

train loss가 낮고 valid loss가 높다는 패턴은 Overfitting의 **신호**이지 단독 증명은 아니다<br>
distribution shift, split leakage, label noise, 서로 다른 transform·전처리 통계도 같은 모양을 만들 수 있으므로 먼저 데이터 파이프라인을 점검한다.

## 6. 진단 함수

아래 함수는 마지막 epoch의 train/valid loss와 accuracy를 보고 간단한 진단 문장을 출력

```python
def diagnose_fit(history, loss_gap_threshold=0.15, acc_gap_threshold=0.10):
    """
    epoch 로그를 바탕으로 학습 상태를 간단히 진단하는 함수입니다.

    history:
        train_loss, valid_loss, train_acc, valid_acc가 들어 있는 딕셔너리입니다.

    loss_gap_threshold:
        train loss와 valid loss 차이가 이 값보다 크면 과적합 가능성을 의심합니다.

    acc_gap_threshold:
        train accuracy와 valid accuracy 차이가 이 값보다 크면 과적합 가능성을 의심합니다.
    """

    # 마지막 epoch의 값을 꺼냅니다.
    # -1은 리스트의 마지막 원소를 의미합니다.
    train_loss = history["train_loss"][-1]
    valid_loss = history["valid_loss"][-1]
    train_acc = history["train_acc"][-1]
    valid_acc = history["valid_acc"][-1]

    # train과 validation 사이의 차이를 계산합니다.
    loss_gap = valid_loss - train_loss
    acc_gap = train_acc - valid_acc

    # 현재 값을 보기 좋게 출력합니다.
    print(f"train_loss:{train_loss:.4f}")
    print(f"valid_loss:{valid_loss:.4f}")
    print(f"train_acc :{train_acc:.4f}")
    print(f"valid_acc :{valid_acc:.4f}")
    print(f"loss_gap  :{loss_gap:.4f}")
    print(f"acc_gap   :{acc_gap:.4f}")

    # 과적합 가능성을 판단합니다.
    # validation loss가 train loss보다 많이 크거나,
    # train accuracy가 validation accuracy보다 많이 높으면 과적합을 의심합니다.
    if loss_gap > loss_gap_threshold or acc_gap > acc_gap_threshold:
        return "Overfitting 가능성이 있습니다. Dropout, weight decay, Early Stopping을 고려하세요."

    # train과 validation 성능이 모두 낮다면 과소적합을 의심합니다.
    if train_acc < 0.60 and valid_acc < 0.60:
        return "Underfitting 가능성이 있습니다. 모델 크기, epoch 수, learning rate를 확인하세요."

    # 위 조건에 걸리지 않으면 현재 기준에서는 비교적 안정적이라고 판단합니다.
    return "현재 로그만 보면 비교적 안정적인 학습 상태입니다."
```

## 7. 대응 방법 정리

1. 같은 사람·환자·원본의 파생 샘플이 split을 가로질러 섞이지 않았는지 확인
2. train/valid의 수집 조건, label 기준과 class 비율이 의도대로인지 확인
3. 전처리 통계는 train에서만 계산했는지, valid에는 랜덤 증강이 없는지 확인
4. train metric과 valid metric을 같은 마지막 weight·eval 조건으로 비교했는지 확인


이 점검 뒤에도 같은 분포의 새 데이터에서 gap이 반복될 때 모델의 fit 문제로 대응

### Underfitting일 때 먼저 시도할 것

1. 모델 용량을 늘린다
2. 학습 epoch를 늘린다
3. learning rate를 조정한다
4. 입력 feature나 전처리를 점검한다


### Overfitting일 때 먼저 시도할 것

1. Dropout을 추가한다
2. weight decay를 사용한다
3. Early Stopping을 적용.
4. 데이터를 더 확보하거나 augmentation을 적용합니다.
5. 모델 크기를 줄입니다.

Early Stopping(조기 종료)을 적용한다는 것은 validation 성능이 더 이상 좋아지지 않으면 예정된 epoch를 모두 채우기 전에 학습을 멈춘다는 뜻

항상 한 번에 하나의 변경만 적용하는 것이 좋다. <br>
여러 개를 동시에 바꾸면 무엇 때문에 성능이 바뀌었는지 알기 어렵다.

## 8. 자주 하는 실수

### 실수 1. train accuracy만 보고 모델이 좋다고 판단합니다

train accuracy가 99%여도 validation accuracy가 70%라면 과적합일 수 있다.

### 실수 2. validation loss가 한 번 올랐다고 바로 실패로 판단합니다

학습 곡선은 조금 흔들릴 수 있습니다. 한 epoch만 보지 말고 여러 epoch의 추세를 보세요.

### 실수 3. 대응 방법을 한 번에 많이 바꿉니다

Dropout, learning rate, hidden size, batch size를 동시에 바꾸면 어떤 변경이 효과가 있었는지 알 수 없다.
