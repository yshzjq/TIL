## 1. 이번에 우리가 배울 것

PyTorch 학습 코드에서 가장 중요한 반복 구조를 배운다

```
optimizer.zero_grad()
outputs = model(inputs)
loss = criterion(outputs, targets)
loss.backward()
optimizer.step()
```

## 2. 학습 step의 전체 순서

### 2-1. 시간 순서로 읽어봅니다

```
step 시작
-> 이전 gradient 제거
-> 현재 parameter로 prediction 생성
-> prediction과 target으로 loss 계산
-> loss에서 parameter까지 gradient 계산
-> gradient로 parameter 업데이트
-> 다음 step
```

현재 step에서는 기존 parameter로 예측과 loss를 계산한 후 parameter를 업데이트하며, 새 parameter는 다음 step의 예측부터 사용된다

### 2-2. 각 단계에서 무엇이 생기나요?

| 코드 직후 | 새로 생기거나 바뀌는 것 | 아직 바뀌지 않는 것 |
| --- | --- | --- |
| `zero_grad()` | 이전 `.grad` 제거 | weight, bias |
| `model(inputs)` | outputs, 계산 그래프 | weight, bias |
| `criterion(...)` | loss Tensor | weight, bias, `.grad` |
| `loss.backward()` | parameter `.grad` | weight, bias |
| `optimizer.step()` | 새 weight, bias | 기존 loss 값 |

### 2-3. loss는 step 후 자동으로 다시 계산되지 않습니다

`optimizer.step()`이 parameter를 바꾸더라도 이미 출력된 `loss` Tensor는 업데이트 전 예측에서 계산된 값이다.<br>
새 parameter의 loss를 보려면 다시 forward해야 합니다.

```python
optimizer.step()
new_outputs = model(inputs)
new_loss = criterion(new_outputs, targets)
```

backward까지는 계산이고, step에서 처음으로 parameter 값이 바뀐다.


학습 step은 보통 다음 순서로 진행됩니다.

| 순서 | 코드 | 역할 |
| --- | --- | --- |
| 1 | `optimizer.zero_grad()` | 이전 gradient 초기화 |
| 2 | `outputs = model(inputs)` | 모델 예측 계산 |
| 3 | `loss = criterion(outputs, targets)` | loss 계산 |
| 4 | `loss.backward()` | gradient 계산 |
| 5 | `optimizer.step()` | parameter 업데이트 |

이 순서는 매우 중요합니다. 특히 `zero_grad()`를 빼먹으면 gradient가 계속 누적될 수 있다

### 3-1. 숫자로 누적을 이해

첫 번째 backward에서 weight gradient가 `2.0`이었다고 가정

```
첫 backward 후 grad = 2.0
```

`zero_grad()` 없이 두 번째 backward에서 새 gradient `3.0`이 계산되면 `.grad`는 `3.0`으로 교체되지 않고 `5.0`이 된다

```
기존 2.0 + 새 3.0 = 누적 grad 5.0
```

따라서 기본 학습에서 두 번째 batch만의 gradient를 사용하려면 새 step 전에 이전 값을 비워야 한다.

### 3-2. 직접 확인하는 코드

```python
optimizer.zero_grad()
loss1.backward()
grad_after_first = model.weight.grad.detach().clone()

# zero_grad 없이 다시 backward
loss2.backward()
grad_after_second = model.weight.grad.detach().clone()

print("first grad:", grad_after_first)
print("accumulated grad:", grad_after_second)
```

### 3-3. gradient accumulation(누적)은 언제 의도적으로 사용하나요?

GPU 메모리 때문에 큰 batch를 한 번에 처리할 수 없을 때 여러 작은 batch의 gradient를 누적한 뒤 한 번 `step()`할 수 있다

```python

# train 데이터를 4분할
micro_batches = [
    batch_A,
    batch_B,
    batch_C,
    batch_D
]
accumulation_steps = micro_batches.len() # 개수

optimizer.zero_grad()
for micro_step, batch in enumerate(micro_batches):
    loss = compute_loss(batch) / accumulation_steps
    loss.backward()
optimizer.step()
```

이 경우에는 의도적으로 중간 `zero_grad()`를 호출하지 않는다<br>
기본 학습과 의도적인 accumulation을 구분해야 한다

### 3-4. `None`과 0 Tensor

`set_to_none=True`는 메모리와 성능 면에서 유리할 수 있고, 다음 backward에서 새 grad가 생성됩니다.<br>
초반에는 둘 다 “이전 step의 gradient를 사용하지 않도록 비운 상태”로 이해하면 된다

---

PyTorch에서는 `backward()`를 호출하면 gradient가 parameter의 `.grad`에 저장됩니다. 이 gradient는 기본적으로 누적된다



그래서 새로운 step을 시작하기 전에 이전 gradient를 비워야 한다

```
optimizer.zero_grad()
```

간단히 말해 `zero_grad()`는 다음 의미한다

```
지난번 문제 풀이 흔적을 지우고,
이번 batch에 대한 gradient를 새로 계산할 준비를 한다
```



### gradient가 0인가, None인가

최근 PyTorch에서 `optimizer.zero_grad()`의 기본 동작은 보통 `.grad`를 0 Tensor로 채우는 대신 `None`으로 설정한다.

다음 `backward()`가 호출되면 새 gradient가 만들어진다.

초반에는 둘 다 “이전 gradient를 다음 step에 누적하지 않도록 비운다”는 의미로 이해하면 충분하다

직접 0 Tensor가 필요하면 `optimizer.zero_grad(set_to_none=False)`를 사용할 수 있다.


## 4. forward와 loss 계산

forward는 입력을 모델에 넣어 예측값을 만드는 단계

```
outputs = model(inputs)
```

그 다음 손실 함수로 예측값과 정답을 비교한다

```
loss = criterion(outputs, targets)
```

예시

```python
import torch
import torch.nn as nn

model = nn.Linear(3, 1)
criterion = nn.MSELoss()

inputs = torch.randn(4, 3)
targets = torch.randn(4, 1)

outputs = model(inputs)
loss = criterion(outputs, targets)

print("outputs shape:", outputs.shape)
print("targets shape:", targets.shape)
print("loss:", loss)
```

## 5. `backward`: gradient 계산


**backward는 parameter를 수정하지 않고, 수정에 사용할 기울기를 `.grad`에 기록한다.**

### 5-1. gradient는 무엇을 뜻하나요?

어떤 weight의 gradient가 `4.0`이라는 것은 현재 위치에서 그 weight를 아주 조금 증가시키면 loss가 증가하는 방향이라는 뜻이다. <br>
단순 SGD는 반대 방향으로 움직인다

```
weight grad = +4.0 -> weight를 줄이는 방향
weight grad = -4.0 -> weight를 늘리는 방향
```

### 5-2. backward 전후를 확인

```python
print(model.weight.grad)  # 보통 None
loss.backward()
print(model.weight.grad)  # Tensor 생성
```

이때 `model.weight` 값 자체는 아직 변하지 않습니다.

### 5-3. `loss.item()`에는 왜 backward할 수 없나요?

`loss.item()`은 계산 그래프와 연결된 Tensor에서 Python 숫자만 꺼낸다

```
loss          -> Tensor, grad_fn 보유, backward 가능
loss.item()   -> Python float, 계산 그래프 없음
```

따라서 기록에는 `loss.item()`을 사용하고, 역전파에는 `loss.backward()`를 사용한다

### 5-4. 같은 그래프에서 backward를 두 번 호출하면

기본 backward 후에는 메모리 절약을 위해 중간 그래프가 해제된다<br>
같은 loss로 다시 backward해야 하는 특별한 경우에만 `retain_graph=True`가 필요하다

일반 학습 loop에서 무조건 사용하면 메모리 사용량이 커지므로 피해야한다.

`loss.backward()`는 loss를 기준으로 각 parameter가 loss에 얼마나 영향을 주었는지 gradient를 계산한다

```
loss.backward()
```

호출 후에는 parameter의 `.grad`를 확인할 수 있다.

```
for name, param in model.named_parameters():
    print(name)
    print("parameter:", param)
    print("gradient :", param.grad)
```

출력되는 gradient는 optimizer가 parameter를 업데이트할 때 사용한다.

`loss.item()`은 Python 숫자를 꺼내는 메서드다. <br>
`loss.item().backward()`는 사용할 수 없습니다. backward는 Tensor인 `loss`에 호출해야 한다


## 6. `step`: parameter 업데이트

**`optimizer.step()`이 실제 weight와 bias를 바꾸는 유일한 단계다.**

### 6-1. 기본 SGD update를 직접 계산

momentum이 없는 SGD에서 learning rate가 `0.1`이라면 다음과 같다

```
expected_weight = weight_before - 0.1 * weight_grad
```

`optimizer.step()` 이후 실제 weight와 비교할 수 있다.

```python
expected = weight_before - lr * weight_grad
optimizer.step()
actual = model.weight.detach().clone()
print(torch.allclose(expected, actual))
```

### 6-2. step 뒤에도 `.grad`는 자동으로 비워지지 않는다

parameter가 바뀌어도 기존 gradient는 `.grad`에 남아 있습니다. 다음 step 시작에서 `zero_grad()`를 호출해야 합니다.

```
step() -> parameter 변경
zero_grad() -> gradient 제거
```

두 함수는 역할이 다릅니다.

### 6-3. `torch.no_grad()`로 직접 update하는 방식과 optimizer

아주 단순한 실습에서는 다음처럼 직접 바꿀 수 있다

```python
with torch.no_grad():
    for param in model.parameters():
        param -= lr * param.grad
```

하지만 momentum, Adam state, weight decay 등 복잡한 규칙을 안전하게 관리하기 위해 optimizer를 사용

---

gradient를 계산했다면 optimizer가 parameter를 업데이트한다

```
optimizer.step()
```

이 한 줄이 실제로 weight와 bias 값을 바꾼다

```
backward(): gradient 계산
step(): parameter 변경
```

## 7. parameter 업데이트 직접 확인하기


**업데이트 검증은 전·후 값뿐 아니라 gradient와 예상 update까지 함께 비교해야 한다.**


### 7-1. 왜 `detach().clone()`을 사용하나요?

```python
weight_before = model.weight.detach().clone()
```

- `detach()`는 계산 그래프 추적에서 분리한다
- `clone()`은 현재 값을 독립적인 새 Tensor로 복사한다

둘 중 하나만 빠지면 업데이트 전 값을 안전하게 보관하지 못하거나 불필요한 그래프 연결이 남을 수 있다

### 7-2. 검증 순서

```
1. weight_before 복사
2. zero_grad
3. forward와 loss
4. backward 후 weight_grad 복사
5. expected_weight 계산
6. step
7. weight_after와 expected_weight 비교
```

### 7-3. parameter가 정말 바뀌었는지 세 가지로 확인

```python
changed = not torch.equal(weight_before, weight_after)
close_to_expected = torch.allclose(weight_after, expected_weight)
update_norm = (weight_after - weight_before).norm().item()

print("changed:", changed)
print("matches SGD formula:", close_to_expected)
print("update norm:", update_norm)
```

`changed=True`만으로는 update가 올바른지 알 수 없다. 
<br>단순 SGD 실험에서는 예상 수식과도 일치하는지 확인.

### 7-4. loss 감소는 한 step만으로 보장되지 않습니다

큰 learning rate, noisy batch, 복잡한 곡면에서는 한 번의 step 뒤 같은 batch loss가 오를 수도 있다.<br> 
parameter update가 발생했는지와 장기적인 학습 개선은 별도 확인 항목이다

---

학습 전후 weight가 바뀌는지 직접 확인해보겠습니다.

```python
import torch
import torch.nn as nn
import torch.optim as optim

# 재현을 위해 seed를 고정합니다.
torch.manual_seed(0)

model = nn.Linear(3, 1)
criterion = nn.MSELoss()
optimizer = optim.SGD(model.parameters(), lr=0.1)

inputs = torch.randn(4, 3)
targets = torch.randn(4, 1)

# 업데이트 전 parameter를 복사해둡니다.
weight_before = model.weight.detach().clone()
bias_before = model.bias.detach().clone()

# 1. gradient 초기화
optimizer.zero_grad()

# 2. forward
outputs = model(inputs)

# 3. loss 계산
loss = criterion(outputs, targets)

# 4. backward
gradient_before_backward = model.weight.grad
loss.backward()

# step 직전에 계산된 gradient를 복사합니다.
weight_grad = model.weight.grad.detach().clone()
bias_grad = model.bias.grad.detach().clone()

# momentum이 없는 SGD의 예상 업데이트를 직접 계산합니다.
expected_weight = weight_before - 0.1 * weight_grad
expected_bias = bias_before - 0.1 * bias_grad

# 5. step
optimizer.step()

weight_after = model.weight.detach().clone()
bias_after = model.bias.detach().clone()

print("gradient before backward:", gradient_before_backward)
print("weight before:", weight_before)
print("weight grad  :", weight_grad)
print("weight expected after:", expected_weight)
print("weight actual after  :", weight_after)
print("bias before:", bias_before)
print("bias grad  :", bias_grad)
print("bias expected after:", expected_bias)
print("bias actual after  :", bias_after)
print("weight formula matches?", torch.allclose(expected_weight, weight_after))
print("bias formula matches?  ", torch.allclose(expected_bias, bias_after))
```
```
gradient before backward: None
weight before: tensor([[-0.0043,  0.3097, -0.4752]])
weight grad  : tensor([[-1.1512,  0.8372, -2.0357]])
weight expected after: tensor([[ 0.1108,  0.2260, -0.2716]])
weight actual after  : tensor([[ 0.1108,  0.2260, -0.2716]])
bias before: tensor([-0.4249])
bias grad  : tensor([-0.3759])
bias expected after: tensor([-0.3873])
bias actual after  : tensor([-0.3873])
weight formula matches? True
bias formula matches?   True
```

`gradient before backward`는 `None`이고, backward 뒤에는 숫자로 된 `weight_grad`, `bias_grad`가 생긴다

즉, momentum이 없는 SGD에서 실제 업데이트가 새 parameter = 기존 parameter - learning_rate × gradient와 일치

## 8. 실전 디버깅 패턴

### 8-1. 1단계: 입력과 출력 계약

```python
print(inputs.shape, inputs.dtype, inputs.device)
print(outputs.shape, outputs.dtype, outputs.device)
print(targets.shape, targets.dtype, targets.device)
```

### 8-2. 2단계: loss가 유한한가요?

```python
print("loss:", loss.item())
assert torch.isfinite(loss)
```

NaN이면 입력 NaN/Inf, 잘못된 수식, 큰 learning rate를 확인

### 8-3. 3단계: gradient가 존재하고 유한한가?

```python
for name, param in model.named_parameters():
    if param.grad is None:
        print(name, "grad is None")
    else:
        print(name, "grad norm:", param.grad.norm().item())
        assert torch.isfinite(param.grad).all()
```

`grad is None`이면 해당 parameter가 forward 계산에 사용되지 않았거나<br>
`requires_grad=False`, `detach()` 등의 연결 단절을 의심한다.

### 8-4. 4단계: parameter가 실제로 바뀌는지

```python
before = {
    name: p.detach().clone()
    for name, p in model.named_parameters()
}
optimizer.step()
for name, p in model.named_parameters():
    print(name, not torch.equal(before[name], p.detach()))
```

### 깨진 코드 학습 중 `torch.no_grad()`를 사용한 경우

```
# 잘못된 예시
with torch.no_grad():
    outputs = model(inputs)
    loss = criterion(outputs, targets)

loss.backward()
```

`torch.no_grad()`는 평가나 추론에서 gradient 추적을 끌 때 사용한다.<br> 학습 step에서는 사용하면 안 된다.
