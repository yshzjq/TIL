## 1. 이번에 배울것

중요한 실험 결과는 파일로 남겨야 한다

| 로그 | 저장 파일 | 의미 |
| --- | --- | --- |
| config log | `config.json` | 어떤 설정으로 실험했는지 저장 |
| metric log | `metrics.csv` | epoch별 loss/accuracy 저장 |

## 2. logging이 필요한 이유

실험 로그가 있으면 아래 질문들에 답할 수 있다.

- learning rate를 얼마로 했나요?
- batch size는 몇이었나요?
- 몇 epoch에서 validation accuracy가 가장 높았나요?
- 어떤 checkpoint가 가장 좋은 모델인가요?
- 지난번 실험과 이번 실험은 무엇이 달랐나요?

## 3. 무엇을 기록해야 하나요?

기본적으로 다음 항목을 기록하는 것이 좋다.

| 범주 | 예시 |
| --- | --- |
| 데이터 | 데이터 출처·버전, split seed·크기 또는 인덱스, train/valid/test transform |
| 모델 | hidden_dim, num_layers, dropout 사용 여부 |
| 학습 설정 | batch_size, learning_rate, optimizer, epochs |
| 결과 | train_loss, valid_loss, train_acc, valid_acc |
| 저장 정보 | best checkpoint 경로 |
| 환경 | Python·PyTorch 버전, device, seed |

최소한 **config와 metric**은 남기는 습관을 들여야 한다

## 4. config를 JSON으로 저장하기

실험 설정은 dictionary로 만들고 JSON 파일로 저장할 수 있습니다.

```python
import json
import platform
from pathlib import Path

import torch

def save_config(config, save_dir):
    """
    실험 설정 dictionary를 config.json 파일로 저장합니다.

    config:
        실험 설정을 담은 dictionary입니다.

    save_dir:
        config.json을 저장할 폴더입니다.
    """

    # 문자열 경로나 Path 객체를 모두 Path 객체로 변환합니다.
    save_dir = Path(save_dir)

    # 저장 폴더가 없으면 생성합니다.
    save_dir.mkdir(parents=True, exist_ok=True)

    # 저장할 파일 경로입니다.
    config_path = save_dir / "config.json"

    # ensure_ascii=False는 한글이 깨지지 않게 저장하기 위한 옵션입니다.
    # indent=2는 사람이 읽기 좋게 들여쓰기합니다.
    with open(config_path, "w", encoding="utf-8") as f:
        json.dump(config, f, ensure_ascii=False, indent=2)

    print(f"config saved to:{config_path}")
```

사용 예시

```python
config = {
    "seed": 42,
    "model": "SimpleMLP",
    "input_dim": 4,
    "hidden_dim": 64,
    "num_classes": 3,
    "batch_size": 32,
    "learning_rate": 0.005,
    "epochs": 30,
    "optimizer": "Adam",
    "data": {
        "name": "example_tabular",
        "version": "v1",
        "split_seed": 42,
        "split_sizes": {"train": 70, "valid": 15, "test": 15},
    },
    "transforms": {
        "train": "standardize with train statistics",
        "valid": "same fixed train statistics",
        "test": "same fixed train statistics",
    },
    "environment": {
        "python": platform.python_version(),
        "torch": torch.__version__,
        "device": "cuda" if torch.cuda.is_available() else "cpu",
    },
}

save_config(config, save_dir="runs/exp001")
```

실제 데이터에서는 이름만 적지 말고 내려받은 버전·파일 hash·고정된 샘플 ID처럼 원본을 다시 식별할 정보도 남긴다<br>
원본 행 순서가 바뀔 수 있다면 split seed만으로는 같은 분할이 보장되지 않으므로 split 인덱스나 group ID도 별도 파일로 저장한다

## 5. epoch metric을 CSV로 저장하기

CSV 파일은 표 형태 로그를 저장하기에 좋습니다.

```python
import csv
import math
from pathlib import Path

METRIC_COLUMNS = [
    "epoch",
    "train_loss",
    "train_acc",
    "valid_loss",
    "valid_acc",
]

def init_metric_csv(save_dir, resume=False):
    """새 로그를 만들거나, 재개할 기존 로그를 확인합니다."""

    save_dir = Path(save_dir)
    save_dir.mkdir(parents=True, exist_ok=True)
    csv_path = save_dir / "metrics.csv"

    if resume:
        if not csv_path.exists():
            raise FileNotFoundError(f"metric log not found: {csv_path}")
        return csv_path

    if csv_path.exists():
        raise FileExistsError(
            f"기존 로그를 덮어쓰지 않습니다: {csv_path}"
        )

    with open(csv_path, "w", newline="", encoding="utf-8") as file:
        writer = csv.writer(file)
        writer.writerow(METRIC_COLUMNS)

    return csv_path
```

새 실험에서는 `resume=False`, checkpoint 재개에서는 `resume=True`를 사용한다<br>
재개할 때는 CSV의 마지막 epoch와 checkpoint의 `completed_epochs`가 같은지 먼저 확인하고, 다음 번호만 추가합니다.<br>
둘이 다르면 바로 append하지 말고 checkpoint의 history를 기준으로 CSV를 다시 생성한다

## 6. print log와 file log 함께 사용하기

화면 출력은 학습 중 바로 확인하기 좋고, 파일 저장은 나중에 분석하기 좋습니다.

```python
def log_epoch(csv_path, epoch, epochs, train_loss, train_acc, valid_loss, valid_acc):
    """
    epoch 결과를 화면에 출력하고 CSV 파일에도 저장합니다.
    """

    # 1. 화면에 보기 좋게 출력합니다.
    print(
        f"Epoch [{epoch:03d}/{epochs:03d}] "
        f"train_loss={train_loss:.4f} "
        f"train_acc={train_acc:.4f} "
        f"valid_loss={valid_loss:.4f} "
        f"valid_acc={valid_acc:.4f}"
    )

    # 2. 같은 정보를 CSV 파일에도 저장합니다.
    append_metric_csv(
        csv_path=csv_path,
        epoch=epoch,
        train_loss=train_loss,
        train_acc=train_acc,
        valid_loss=valid_loss,
        valid_acc=valid_acc
    )
```


로그는 학습 코드의 부가 기능이 아니라, 실험 관리의 핵심이다.<br>
나중에 성능 비교 리포트를 작성하려면 로그가 반드시 필요하다

## 7. 자주 하는 실수

### 실수 1. config를 저장하지 않는 경우

metric은 남아 있는데 learning rate, hidden_dim, batch size가 기억나지 않으면 실험 비교가 어렵다

### 실수 2. CSV header를 빼먹는 경우

```
# 나중에 어떤 column인지 알기 어렵다
writer.writerow([epoch, train_loss, train_acc, valid_loss, valid_acc])
```

처음 파일을 만들 때 header를 저장한다

```
writer.writerow(["epoch", "train_loss", "train_acc", "valid_loss", "valid_acc"])
```

### 실수 3. 매 epoch마다 CSV를 새로 쓰는 경우

`"w"` mode는 파일을 새로 쓴다<br>
epoch 결과를 추가할 때는 `"a"` mode를 사용해야 합니다.
