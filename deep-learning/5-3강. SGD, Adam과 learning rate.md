## 1. 이번에 배울것

모델 parameter를 실제로 바꾸는 역할은 **optimizer**가 담당한다

```
loss 계산 -> gradient 계산 -> optimizer가 parameter 업데이트
```

## 🖼️ learning rate에 따른 loss curve 비교

<img src="{{ '/assets/images/uploads/deep-learning/learning rate에 따른 loss curve 비교.png' | relative_url }}" alt="learning rate에 따른 loss curve 비교.png" loading="lazy">

learning rate 비교

learning rate가 너무 작으면 loss가 느리게 줄고, 적절하면 안정적으로 줄며, 너무 크면 loss가 흔들리거나 발산할 수 있습니다.

## 2. Optimizer는 무엇을 하나요?

optimizer는 loss를 직접 보지 않고, backward가 parameter마다 계산해 둔 gradient를 읽는다


### 2-1. loss, gradient, optimizer의 역할을 분리

```
loss function -> 현재 예측의 오차를 계산
backward      -> 각 parameter가 오차에 미친 영향인 gradient 계산
optimizer     -> gradient를 사용해 parameter 값을 실제 변경
```

예를 들어 weight가 `3.0`, gradient가 `2.0`, learning rate가 `0.1`인 단순 SGD라면 다음과 같습니다.

```
new_weight = 3.0 - 0.1 * 2.0
           = 2.8
```

반대로 gradient가 `-2.0`이면 다음과 같습니다.

```
new_weight = 3.0 - 0.1 * (-2.0)
           = 3.2
```
gradient 부호에 따라 parameter가 움직이는 방향이 달라진다

### 2-2. gradient의 반대 방향으로 가는 이유

Gradient는 현재 위치에서 loss가 가장 빠르게 증가하는 방향을 가리킨다<br>
loss를 줄이려면 그 반대 방향으로 이동.

```
증가 방향: +gradient
감소 방향: -gradient
```

### 2-3. optimizer가 정답 parameter를 한 번에 아는 것은 아니다
현재 batch와 현재 위치의 gradient만 보고 작은 update를 반복<br>
그래서 데이터 순서, batch 구성, learning rate에 따라 이동 경로가 달라진다

optimizer는 backward가 만든 gradient를 읽어, parameter를 loss가 작아지는 방향으로 한 step 이동시킨다

Optimizer는 parameter를 loss가 줄어드는 방향으로 업데이트

신경망의 parameter는 다음과 같습니다.

```
weight
bias
```
학습 과정에서 `loss.backward()`를 호출하면 각 parameter에 대한 gradient가 계산된다.<br>
optimizer는 이 gradient를 보고 parameter를 조금씩 바꾼다.

```
새 parameter = 기존 parameter - learning_rate × gradient
```

이 식은 SGD를 단순화한 직관입니다.

loss 함수는 “얼마나 틀렸는지”를 계산하고, optimizer는 “어느 방향으로 parameter를 바꿀지”를 결정

## 3. Learning rate란 무엇인가요?

learning rate는 단순한 속도가 아니라, gradient를 실제 이동량으로 바꾸는 배율

### 3-1. 같은 learning rate라도 update 크기는 다를 수 있습니다

```
update amount = learning_rate * gradient
```

learning rate가 `0.1`로 같아도 gradient가 `0.01`이면 `0.001`만 움직이고, gradient가 `100`이면 `10`만큼 움직입니다.

```
lr=0.1, grad=0.01 -> update=0.001
lr=0.1, grad=100  -> update=10
```

따라서 loss가 폭주할 때는 learning rate뿐 아니라 gradient 크기와 입력 스케일도 함께 확인해야한다.

### 3-2. 너무 큰 learning rate의 overshoot

최소점이 weight `2.0` 근처인데 현재 `0.0`에서 한 번에 `3.0`만큼 움직이면 최소점을 지나 `3.0`으로 넘어갑니다. 다음 step에서는 반대 방향 gradient가 생겨 다시 크게 되돌아올 수 있습니다.

```
0.0 -> 3.0 -> -1.0 -> 4.5 ...
```

이런 왕복이 반복되면 loss가 진동하고, update가 더 크면 값이 계속 커져 발산할 수 있다

### 3-3. 너무 작은 learning rate도 안전하기만 한 것은 아닙니다

학습 시간이 지나치게 오래 걸리고, 제한된 epoch 안에 충분히 좋은 영역에 도달하지 못할 수 있다. <br>
loss가 아주 천천히 줄어드는지, 완전히 평평한지 구분해야 한다.

### 3-4. 적절한 값은 고정된 공식이 아닙니다

모델 구조, batch size, optimizer, normalization, scheduler가 바뀌면 적절한 learning rate도 달라진다<br>
시작값을 후보로 삼고 loss curve와 validation 성능을 비교

---

Learning rate는 parameter를 한 번에 얼마나 크게 움직일지 정하는 값입니다.

| learning rate | 의미 |
| --- | --- |
| 너무 작음 | 천천히 학습되어 시간이 오래 걸립니다. |
| 적절함 | loss가 안정적으로 줄어듭니다. |
| 너무 큼 | loss가 흔들리거나 발산할 수 있습니다. |

예를 들어 gradient가 `2.0`이고 learning rate가 `0.1`이라면 parameter는 `0.2`만큼 움직인다

```
update amount = 0.1 × 2.0 = 0.2
```

learning rate가 `10.0`이라면 같은 gradient에서 `20.0`만큼 움직이므로 너무 크게 튈 수 있다


## 4. learning rate가 너무 작거나 크면 어떻게 되나요?

### 4-1. 왜 초기 parameter를 같게 해야 하나요?

모델을 새로 만들 때마다 weight와 bias가 다르게 초기화된다.<br>
그러면 최종 loss 차이가 learning rate 때문인지 초기값 때문인지 구분하기가 어렵다

```
비교하려는 변수: learning rate
같게 둘 조건: 데이터, 초기 parameter, optimizer 종류, step 수
```

`state_dict()`를 복사하는 것은 실험의 출발선을 맞추는 과정입니다.

### 4-2. first loss가 같은지 먼저 확인합니다

같은 초기 parameter와 같은 데이터라면 update 전 첫 loss가 같아야 합니다. 첫 loss부터 다르면 비교 조건이 섞였다는 신호다.

### 4-3. curve를 어떻게 읽나요?

```
작은 lr: 완만하게 감소하지만 제한된 step에서 높은 loss
적절한 lr: 빠르고 안정적으로 감소
큰 lr: 진동, 급격한 증가, inf 또는 NaN 가능
```

log scale 그래프에서는 세로축 한 칸의 차이가 단순한 덧셈이 아니라 10배, 100배 차이일 수 있습니다.<br>
큰 learning rate 곡선이 위로 직선처럼 솟는다면 지수적으로 폭증하는 상황일 수 있다

### 4-4. 큰 lr 실험이 발산했다고 항상 코드 오류는 아니다

의도적으로 너무 큰 값을 넣어 불안정성을 관찰한 실험이라면 발산 자체가 결과입니다.
<br>다만 실제 학습에서는 `torch.isfinite(loss)`와 gradient norm을 확인해 조기에 중단한다

```python
if not torch.isfinite(loss):
    raise RuntimeError("loss became non-finite")
```

간단한 선형 회귀 문제에서 learning rate를 비교

```python
import torch
import torch.nn as nn
import torch.optim as optim

# 재현을 위해 seed를 고정합니다.
torch.manual_seed(0)

# y = 2x + 1에 가까운 데이터를 만듭니다.

# -1부터 1까지 일정한 간격으로 숫자 100개를 만듭니다.
# torch.linspace(-1, 1, 100), shape은 (100,)입니다.
# .unsqueeze(1) 해서 x.shape 는 (100,1)
x = torch.linspace(-1, 1, 100).unsqueeze(1)

# weight = 2  , bias = 1
# 잡음 = 0.1 * torch.randn_like(x), x와 동일한 모양 (100, 1)의 무작위 숫자를 만든다
# 실제 y는 정확한 직선 위가 아니라 직선 주변에 조금씩 흩어진다
# 이를 추가하는 이유는 현실의 데이터에도 측정 오차나 설명할 수 없는 변동이 있기 때문이다.
y = 2 * x + 1 + 0.1 * torch.randn_like(x)

# 모든 learning rate가 같은 출발점에서 시작하도록
# 하나의 초기 parameter를 복사해 둡니다.
base_model = nn.Linear(1, 1)
initial_state = {
    name: value.detach().clone()
    for name, value in base_model.state_dict().items()
}

def train_with_lr(lr, steps=50):
    """
    주어진 learning rate로 간단한 선형 회귀 모델을 학습하고 loss 기록을 반환합니다.
    """
    model = nn.Linear(1, 1)
    model.load_state_dict(initial_state)

    criterion = nn.MSELoss()
    optimizer = optim.SGD(model.parameters(), lr=lr)

    losses = []

    for step in range(steps):
        # 1. 이전 step의 gradient를 초기화합니다.
        optimizer.zero_grad()

        # 2. 모델 예측을 계산합니다.
        pred = model(x)

        # 3. loss를 계산합니다.
        loss = criterion(pred, y)

        # 4. gradient를 계산합니다.
        loss.backward()

        # 5. parameter를 업데이트합니다.
        optimizer.step()

        losses.append(loss.item())

    return losses

loss_small = train_with_lr(lr=0.001)
loss_good = train_with_lr(lr=0.1)
loss_large = train_with_lr(lr=1.5)

print("small lr first/last:", loss_small[0], loss_small[-1])
print("good lr first/last :", loss_good[0], loss_good[-1])
print("large lr first/last:", loss_large[0], loss_large[-1])
```

```python
import matplotlib.pyplot as plt

plt.figure(figsize=(8, 4))
plt.plot(loss_small, label="lr=0.001")
plt.plot(loss_good, label="lr=0.1")
plt.plot(loss_large, label="lr=1.5")
plt.xlabel("step")
plt.ylabel("loss")
plt.yscale("log")  # 작은 값과 폭증하는 값을 한 그래프에서 비교합니다.
plt.legend()
plt.show()
```

`lr=0.001`은 50 step 동안 천천히 줄고, `lr=0.1`은 안정적으로 빠르게 줄지만,<br>
`lr=1.5`는 너무 큰 이동 때문에 loss가 약 `2.9 × 10^29`까지 폭증한다 <br>

세 실험은 데이터와 초기 parameter가 같고 learning rate만 다르다. 

그래프에서 `lr=0.001`은 50 step 안에 천천히 감소하고, `lr=0.1`은 더 빠르게 감소하며, <br>
`lr=1.5`는 너무 큰 이동 때문에 loss가 커지는 양상이 확인된다

실행 환경에 따라 정확한 소수점 값은 달라질 수 있으므로 곡선의 방향을 비교한다

이 예시는 매 step 전체 100개 샘플로 gradient를 계산하는 full-batch gradient descent 실험이다.<br> 
PyTorch optimizer 이름은 SGD이지만, stochastic 또는 mini-batch 성질은 DataLoader에서 일부 샘플 batch를 꺼내 gradient를 근사할 때 생긴다

적절한 learning rate는 데이터, 모델, batch size, optimizer에 따라 달라진다. 
<br>처음에는 `1e-3`, `1e-4`, `1e-2` 같은 값을 비교해보는 습관을 가지면 좋다.

Full-batch gradient descent는 한 번 parameter를 업데이트할 때 전체 학습 데이터를 모두 사용해 gradient를 계산하는 방식

## 5. SGD 직관 이해하기

**기본 SGD는 현재 step의 gradient만 보고 모든 parameter에 같은 전역 learning rate 규칙을 적용**

### 5-1. stochastic은 optimizer 이름보다 gradient 계산 방식과 연결된다

전체 데이터의 정확한 gradient 대신 mini-batch로 추정한 gradient를 사용하므로 batch마다 방향이 조금씩 달라질 수 있다.

```
전체 데이터 gradient -> 더 안정적이지만 계산 비용 큼
mini-batch gradient   -> 빠르지만 noise 포함
```

이 noise가 항상 나쁜 것은 아니며, 특정 좁은 경로에 갇히지 않고 일반화에 도움이 되는 경우도 있다.

### 5-2. momentum을 넣으면 무엇이 달라지나요?

기본 SGD는 현재 gradient만 사용하지만 momentum은 이전 이동 방향을 누적해 일관된 방향으로 더 밀고, 좌우 진동은 줄이는 효과를 낸다.

```python
optimizer = optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9,
)
```

### 5-3. SGD가 단순하다는 것은 약하다는 뜻이 아닙니다

적절한 learning rate schedule과 momentum을 사용하면 좋은 일반화 성능을 보일 수 있다.<br>
Adam보다 튜닝이 더 필요할 수 있지만 항상 열등한 optimizer는 아니다

SGD는 **Stochastic Gradient Descent**의 줄임말입니다. 기본 아이디어는 단순하다

```
gradient 방향을 보고,
loss가 가장 빠르게 증가하는 방향의 반대 방향으로 parameter를 이동
```

```python
import torch.nn as nn
import torch.optim as optim

sgd_example_model = nn.Linear(3, 1)
optimizer_sgd_example = optim.SGD(sgd_example_model.parameters(), lr=0.01)
```

SGD는 단순하고 직관적이지만, 상황에 따라 학습이 느리거나 learning rate에 민감할 수 있다

## 6. Adam 직관 이해하기


**Adam은 learning rate를 없애는 optimizer가 아니라, 전역 learning rate에 parameter별 보정 비율을 추가하는 optimizer다.**

### 6-1. 무엇을 기억하나요?

Adam은 최근 gradient의 방향에 대한 이동 평균과 gradient 크기 제곱의 이동 평균을 저장한다.

```
1차 모멘트 m: 최근 gradient 방향의 평균
2차 모멘트 v: 최근 gradient 크기 제곱의 평균
```

방향이 꾸준한 parameter는 그 흐름을 활용하고, gradient 크기가 매우 큰 parameter는 분모의 보정으로 update가 완화된다

### 6-2. parameter마다 다른 실제 step이 만들어진다

같은 전역 `lr=0.001`을 사용해도 각 parameter의 gradient 이력에 따라 실제 update 크기가 달라진다

```
parameter A: gradient가 자주 큼 -> 상대적으로 보수적 update
parameter B: gradient가 작고 일관됨 -> 상대적으로 더 적극적 update 가능
```

### 6-3. Adam이 자동으로 최적값을 찾는 것은 아닙니다

- 전역 learning rate는 여전히 중요합니다.
- validation 성능과 일반화가 항상 SGD보다 좋은 것은 아니다
- optimizer state를 추가로 저장하므로 메모리 사용량이 큽니다.

### 6-4. 매 학습 step마다 optimizer 객체를 다시 생성하면 안 된다

**Adam의 `m`, `v`, step count가 매번 초기화되기 때문이다.** <br>
그러면 gradient 이력을 반영하는 Adam의 핵심 특성이 사라진다

Adam은 gradient 이력을 이용해 parameter별 update를 보정하지만,<br>learning rate 선택과 실험 비교는 여전히 필요하다


Adam은 딥러닝 실습에서 매우 자주 사용하는 optimizer다.

기본 SGD는 하나의 전역 learning rate를 사용하지만 parameter마다 gradient가 다르므로 실제 이동량은 서로 다르다.

Adam은 gradient의 이동 평균과 gradient 제곱의 이동 평균을 사용해 parameter별 업데이트 크기를 적응적으로 조절

Adam이 항상 더 좋은 것은 아니며, 같은 데이터·초기값·평가 기준에서 비교해야 합니다.

PyTorch에서는 다음처럼 사용합니다. 이 블록도 독립 실행을 위해 별도 모델을 만듭니다.

```python
import torch.nn as nn
import torch.optim as optim

adam_example_model = nn.Linear(3, 1)
optimizer_adam_example = optim.Adam(adam_example_model.parameters(), lr=0.001)
```

SGD와 Adam을 아주 단순하게 비교하면 다음과 같습니다.

| Optimizer | 직관 | 자주 쓰는 lr 예시 |
| --- | --- | --- |
| SGD | gradient 방향으로 단순 이동 | `0.1`, `0.01` |
| Adam | gradient 흐름을 반영해 적응적으로 이동 | `0.001`, `0.0001` |

## 7. PyTorch optimizer 코드 패턴

### 7-1. 왜 모델을 다시 만들면 optimizer도 다시 만들어야 하나요?

```python
model = nn.Linear(10, 2)
optimizer = optim.Adam(model.parameters(), lr=0.001)

model = nn.Linear(10, 2)  # 새 parameter 객체
```

변수 이름 `model`은 새 객체를 가리키지만 optimizer는 여전히 이전 parameter를 참조한다. 

새 모델을 학습하려면 optimizer도 새로 생성해야 합니다.


### 7-2. optimizer는 학습 loop 밖에서 한 번 생성해야 한다

```python
optimizer = optim.Adam(model.parameters(), lr=0.001)

for batch in loader:
    optimizer.zero_grad()
    ...
    optimizer.step()
```

SGD momentum이나 Adam의 내부 state를 step 사이에 유지하기 위해 같은 optimizer 객체를 반복 사용한다.

### 7-3. 여러 parameter group을 사용할 수도 있습니다

층마다 learning rate를 다르게 설정할 수 있습니다.

```python
optimizer = optim.Adam([
    {"params": model.backbone.parameters(), "lr": 1e-4},
    {"params": model.head.parameters(), "lr": 1e-3},
])
```

이는 fine-tuning에서 자주 활용되지만, 먼저 모든 parameter가 정확히 한 group에 포함되었는지 확인해야 한다

### 7-4. checkpoint에 optimizer state가 필요한 이유

모델 weight만 저장하면 예측은 복원할 수 있지만, Adam의 누적 모멘트와 step 수는 사라진다.<br>
학습을 정확히 이어가려면 `optimizer.state_dict()`도 함께 저장

Optimizer는 생성할 때 전달받은 parameter만 업데이트한다.<br>
두 optimizer를 공정하게 비교하려면 같은 모델 하나에 둘을 동시에 연결하지 말고, **같은 초기값을 복사한 별도 모델**을 사용한다

```python
import torch
import torch.nn as nn
import torch.optim as optim

torch.manual_seed(42)

model_sgd = nn.Linear(10, 2)
model_adam = nn.Linear(10, 2)
model_adam.load_state_dict(model_sgd.state_dict())

optimizer_sgd = optim.SGD(model_sgd.parameters(), lr=0.01)
optimizer_adam = optim.Adam(model_adam.parameters(), lr=0.001)

same_start = all(
    torch.equal(p_sgd, p_adam)
    for p_sgd, p_adam in zip(model_sgd.parameters(), model_adam.parameters())
)
assert same_start
```
