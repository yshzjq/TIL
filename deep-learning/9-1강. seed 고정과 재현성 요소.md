## 1. 이번에 우리가 배울 것

딥러닝에서는 결과가 매번 조금씩 달라질 수 있다.
그 이유는 모델 초기화, 데이터 섞기, GPU 연산 등 여러 곳에 randomness가 있기 때문이다.

실험 결과를 최대한 재현 가능하게 만들기 위해 seed를 고정하는 방법 배운다

## 2. 재현성이란 무엇인가요?

seed와 재현성 요소


Python random <br>
NumPy random <br>
PyTorch random <br>
CUDA random <br>
DataLoader shuffle <br>


재현성은 같은 조건에서 실험을 다시 실행했을 때 비슷하거나 같은 결과를 얻을 수 있는 성질이다

| 이유 | 설명 |
| --- | --- |
| 실험 비교 | 모델 A와 모델 B의 차이가 진짜 구조 차이인지 확인 |
| 디버깅 | 코드 수정 후 결과가 달라졌을 때 원인을 찾기 쉬워진다. |
| 리포트 작성 | 실험 결과를 다른 사람이 다시 확인할 수 있어야 한다 |
| 팀 협업 | 같은 코드와 설정으로 팀원이 비슷한 결과를 재현할 수 있어야 한다. |

seed를 고정한다고 해서 모든 환경에서 완전히 같은 결과가 항상 보장되는 것은 아니다

PyTorch release, commit, platform이 달라지면 완전한 재현이 보장되지 않을 수 있고, CPU와 GPU 사이에서도 결과가 다를 수 있다<br>
-> seed가 같아도 실행 환경이 달라지면 결과가 완전히 같지 않을 수 있다

 - release(릴리스): 배포된 PyTorch 버전<br>
예: PyTorch 2.5와 PyTorch 2.6은 내부 연산 방식이나 사용 알고리즘이 달라질 수 있다.

 - commit(커밋): PyTorch 소스 코드의 특정 변경 시점<br>
개발 버전이나 직접 빌드한 PyTorch는 같은 버전명처럼 보여도 내부 코드가 다를 수 있다.<br> Git에서 “어느 시점의 코드인가”를 나타내는 값입니다.

 - platform(플랫폼): 실행되는 운영체제와 하드웨어 환경<br>
예: Windows와 Linux, Intel CPU와 AMD CPU, NVIDIA GPU 종류 등이 해당합니다.



## 3. 결과가 달라지는 주요 원인

딥러닝 코드에서 randomness가 발생하는 대표적인 위치는 다음과 같다.

| 위치 | 예시 |
| --- | --- |
| Python random | Python 기본 난수 |
| NumPy random | NumPy 기반 샘플링 |
| PyTorch random | Tensor 생성, weight 초기화 |
| CUDA random | GPU 연산 및 CUDA 난수 |
| DataLoader shuffle | batch 순서 섞기 |
| random split | train/valid 데이터 분할 |

따라서 seed를 하나만 고정하는 것보다, 여러 난수 생성기를 함께 고정하는 것이 좋다.

## 4. seed 고정 함수 만들기

아래 함수는 가장 기본적인 seed 고정 패턴이다

```python
import random
import numpy as np
import torch

def set_seed(seed=42):
    """
    Python, NumPy, PyTorch의 random seed를 고정합니다.

    seed:
        실험을 재현하기 위해 사용할 정수값입니다.
    """

    # Python 기본 random 모듈의 seed를 고정합니다.
    random.seed(seed)

    # NumPy random seed를 고정합니다.
    np.random.seed(seed)

    # PyTorch CPU random seed를 고정합니다.
    torch.manual_seed(seed)

    # CUDA GPU를 사용할 수 있다면 CUDA random seed도 고정합니다.
    if torch.cuda.is_available():
        torch.cuda.manual_seed(seed)
        torch.cuda.manual_seed_all(seed)
```

사용 예시

```python
set_seed(42)

x1 = torch.randn(3)

set_seed(42)

x2 = torch.randn(3)

print(x1)
print(x2)
print(torch.allclose(x1, x2))
```

같은 seed를 다시 설정한 뒤 같은 random Tensor를 만들면 같은 값이 나온다

## 5. DataLoader와 random split에서 seed 사용하기

`random_split`이나 `DataLoader`의 shuffle도 재현성에 영향을 준다

```python
from torch.utils.data import TensorDataset, DataLoader, random_split

# seed는 모델과 난수를 만들기 전에 고정합니다.
set_seed(42)

X = torch.randn(100, 4)
y = torch.randint(0, 3, size=(100,))
dataset = TensorDataset(X, y)

# 데이터 분할과 매 epoch의 shuffle은 서로 다른 generator로 관리합니다.
split_generator = torch.Generator().manual_seed(42)
train_dataset, valid_dataset = random_split(
    dataset,
    [80, 20],
    generator=split_generator,
)

loader_generator = torch.Generator().manual_seed(42)
train_loader = DataLoader(
    train_dataset,
    batch_size=16,
    shuffle=True,
    generator=loader_generator,
    num_workers=0,
)

first_batch_x, first_batch_y = next(iter(train_loader))
print(first_batch_x.shape, first_batch_y.shape)
```

출력

```
torch.Size([16, 4]) torch.Size([16])
```

`DataLoader`에 generator를 넘겨도 generator 상태는 epoch마다 진행하므로, 각 epoch의 shuffle 순서는 달라진다<br> 
같은 seed와 같은 실행 순서로 처음부터 다시 실행하면 그 순서열을 재현할 수 있다.

num_workers>0으로 바꾸면 worker별 난수 초기화와 라이브러리별 난수 사용도 별도로 점검해야 한다


## 6. 이 기초 과정에서 보장하는 재현성 범위

재현성은 목적에 따라 다음처럼 구분해서 생각하면 좋다.

| 목적 | 필요한 상태 | 
| --- | ---  |
| 처음부터 다시 실행 | seed, 데이터 분할, 코드와 환경 |
| 일반적인 학습 재개 | 모델, optimizer, 완료 epoch, 기록 |
| 완료된 epoch 다음부터 정확히 재개 | 위 상태 + Python/NumPy/PyTorch/CUDA 난수 상태 + DataLoader generator 상태 |


위 표의 "재개"는 **한 epoch의 모든 batch 처리와 history 기록이 끝난 뒤 저장한 checkpoint에서, 다음 epoch를 시작하는 경우**만 뜻한다. 

같은 코드, 데이터, 분할, 라이브러리와 장치 환경을 사용하고, 다음 DataLoader iterator를 만들기 전에 상태를 복원해야 한다

seed만 다시 지정하면 중단 시점의 난수 상태로 돌아가지 않는다

정확한 완료-epoch 경계 재개에는 checkpoint에 현재 난수 상태와 `loader_generator` 상태를 함께 저장하고 복원해야 한다.

seed와 상태를 모두 관리해도 PyTorch 버전, 플랫폼, 장치나 사용 연산이 달라지면 비트 단위 동일 결과가 보장되지 않을 수 있다.

## 7. 자주 하는 실수

### 실수 1. 모델을 만든 뒤 seed를 고정하는 경우

```python
model = torch.nn.Linear(4, 3)
set_seed(42)
```

이 경우 이미 모델 weight가 초기화된 뒤입니다. seed는 모델을 만들기 전에 고정해야 한다

```python
set_seed(42)
model = torch.nn.Linear(4, 3)
```

### 실수 2. random split generator를 빼먹는 경우

```python
train_dataset, valid_dataset = random_split(dataset, [80, 20])
```

이 코드는 실행마다 split이 달라질 수 있다.

```python
generator = torch.Generator().manual_seed(42)
train_dataset, valid_dataset = random_split(dataset, [80, 20], generator=generator)
```

### 실수 3. 재개할 때 seed 값만 다시 지정하는 경우

seed 값을 다시 지정하면 난수열의 처음으로 돌아갈 뿐, checkpoint 저장 시점으로 돌아가지는 않는다. <br>
완료된 epoch 다음부터 정확히 재개하려면 모델과 optimizer뿐 아니라 난수 상태와 DataLoader generator 상태를 저장·복원해야 한다.<br>
PyTorch 버전, 장치, 데이터 분할과 주요 hyperparameter도 함께 기록해야 한다.
