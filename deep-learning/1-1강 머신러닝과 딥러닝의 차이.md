## 2. 규칙 기반, 머신러닝, 딥러닝 접근 비교

예를 들어 고객 문의 메시지를 보고 “환불 문의인지 아닌지” 분류한다고 생각

### 2-1. 규칙 기반 접근

```python
text = "상품을 반품하고 환불받고 싶어요."

if "환불" in text or "반품" in text:
    label = "환불 문의"
else:
    label = "기타 문의"

print(label)
```

출력은 다음과 같습니다.

```
환불 문의
```

문장에 `환불`과 `반품`이 모두 들어 있지만 `or` 조건은 하나만 참이어도 전체가 참이므로 `환불 문의`가 출력됩니다.

규칙 기반 접근은 사람이 직접 조건을 작성합니다.

장점은 단순하고 빠르다는 점입니다.

하지만 표현이 조금만 바뀌면 놓치기 쉽습니다.

```
"돈을 돌려받고 싶어요."
"결제 취소 가능한가요?"
"받은 상품을 돌려보내고 싶어요."
```

위 문장들은 모두 환불이나 취소와 관련이 있지만, 환불이나 반품이라는 단어가 없을 수도 있다.

### 2-2. 머신러닝 접근

머신러닝에서는 사람이 특징을 설계한다.

| 특징 | 예시 |
| --- | --- |
| 특정 단어 포함 여부 | 환불, 취소, 반품 포함 여부 |
| 문장 길이 | 글자 수, 단어 수 |
| 문의 카테고리 | 배송, 결제, 상품, 계정 |
| 이전 문의 횟수 | 고객의 과거 문의 수 |

모델은 이 특징들을 보고 분류 규칙을 학습한다.

```
입력 데이터
-> 사람이 설계한 특징
-> 머신러닝 모델
-> 예측 결과
```

### 2-3. 딥러닝 접근

딥러닝에서는 모델이 데이터 안에서 유용한 특징 표현을 스스로 학습한다

```
입력 데이터
-> 신경망 모델
-> 내부 표현 학습
-> 예측 결과
```

텍스트 분류를 예로 들면, 딥러닝 모델은 단어 하나만 보는 것이 아니라 문장 전체의 패턴, 단어 순서, 문맥을 활용할 수 있다.

미지 분류에서는 사람이 귀 모양, 눈 위치, 털 색깔 같은 특징을 일일이 설계하지 않아도, CNN 같은 모델이 픽셀에서 점점 복잡한 특징을 학습한다

⭐ **중요**

입문 단계에서는 머신러닝과 딥러닝의 차이를 **특징 표현을 얼마나 모델이 함께 학습하느냐**로 이해하면 좋다

```
전통적인 머신러닝: 사람이 입력 특징을 주로 설계하고 모델이 그 특징의 패턴을 학습한다.
딥러닝: 여러 층이 원본 입력에서 예측에 유용한 특징 표현까지 함께 학습한다.
```

위 구분은 이해를 위한 대표적 구분이다. 전통적인 머신러닝도 자동 특징 변환을 사용할 수 있고, 딥러닝도 데이터 전처리와 입력 표현 설계가 필요하다.

## 3. 특징 설계와 표현 학습

특징 설계(머신러닝)는 원본 데이터를 모델이 이해하기 쉬운 숫자 형태로 바꾸는 작업이다.<br>
표 데이터에서 나이, 구매 횟수, 평균 결제 금액 같은 feature를 고르는 작업이 대표적인 예다.<br>
반면 표현 학습(딥러닝)은 모델이 원본 데이터에서 예측에 유용한 표현을 직접 찾아가는 방식이다.<br>

위 그림을 딥러닝 관점으로 해석하면 다음과 같습니다.

```
원본 데이터
-> 모델 내부에서 feature representation 생성
-> task-specific model 또는 출력층
-> 예측
-> loss 계산
```

딥러닝이 “특징을 자동으로 학습한다”는 말은 사람이 아무것도 하지 않아도 된다는 뜻이 아니다.<br>
데이터 품질, 문제 정의, label 설계, 모델 구조, loss 선택은 여전히 사람이 잘 설계해야 한다.

## 4. 딥러닝이 잘 맞는 문제

딥러닝은 특히 아래 조건에서 강점을 가집니다.

| 조건 | 설명 | 예시 |
| --- | --- | --- |
| 데이터가 많습니다 | 신경망은 많은 데이터에서 복잡한 패턴을 학습합니다. | 이미지 분류, 음성 인식 |
| 입력이 복잡합니다 | 이미지, 텍스트, 음성처럼 사람이 특징을 직접 설계하기 어렵습니다. | 문서 분류, 리뷰 감성 분석 |
| 비선형 관계가 강합니다 | 단순한 직선/규칙으로 설명하기 어렵습니다. | 이상 탐지, 복잡한 수요 예측 |
| end-to-end 학습이 유리합니다 | 입력에서 특징을 추출하고 최종 예측을 만드는 과정까지 하나의 연결된 모델 안에서 함께 학습한다 | 객체 탐지, 번역 |

* End-to-End 학습 : 입력부터 최종 출력까지의 과정을 하나로 연결해서 함께 학습하는 방식

Private LLM 트랙에서는 이후 아래와 같은 문제로 연결될 수 있습니다.

```
고객 문의 intent classification
도메인 문서 분류
RAG 검색 결과 relevance classifier
답변 안전성/개인정보 포함 여부 분류기
문서 요약 품질 평가 모델
```

## 5. 딥러닝이 항상 정답은 아닌 이유

딥러닝은 강력하지만 항상 가장 좋은 선택은 아닙니다.

| 상황 | 이유 |
| --- | --- |
| 데이터가 너무 적습니다 | 처음부터 큰 신경망을 학습하면 일반화하기 어렵습니다. 다만 사전학습 모델을 활용하는 전이학습에서는 적은 데이터로도 좋은 결과를 얻는 경우가 있습니다. |
| 문제 규칙이 매우 명확합니다 | 단순 조건문이 더 빠르고 설명 가능합니다. |
| 해석 가능성이 매우 중요합니다 | 복잡한 신경망은 의사결정 과정을 설명하기 어려울 수 있습니다. |
| 계산 자원이 부족합니다 | 학습 시간이 길고 GPU가 필요할 수 있습니다. |
| 빠른 baseline이 필요합니다 | 간단한 ML 모델로 먼저 기준 성능을 잡는 것이 좋습니다. |

큰 신경망 : 층(layer)이 많고, 뉴런 수가 많고, 학습해야 할 파라미터(weight, bias)가 아주 많은 모델

일반화 : 학습할 때 보지 못한 새로운 데이터에서도 잘 맞히는 능력

데이터가 너무 적어서 큰 신경망에다가 학습하면 쉽게 말하면 모델이 답을 외우게 된다 (모델이 학습해야 할 파라미터가 학습데이터 보다 많으면 학습데이터를 외우게 된다)


⛔ **주의사항**

딥러닝을 쓰면 무조건 성능이 좋아진다고 생각하면 안된다

실무에서는 먼저 간단한 baseline을 만들고, 딥러닝이 실제로 개선을 만드는지 비교해야 한다

## 정리

```
규칙 기반은 사람이 조건을 직접 작성합니다.
머신러닝은 사람이 특징을 설계하고 모델이 패턴을 학습합니다.
딥러닝은 모델이 특징 표현까지 함께 학습합니다.
딥러닝은 복잡한 데이터에 강하지만 항상 정답은 아닙니다.
```
