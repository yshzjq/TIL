## 1. 이번에 배울것

데이터 파이프라인을 실제 학습 전에 어떻게 점검하는지 배운다

딥러닝 코드에서 오류는 모델보다 데이터에서 먼저 생기는 경우가 많다

```
입력 shape가 모델과 맞지 않음
label dtype이 loss 함수와 맞지 않음
batch 차원이 빠짐
이미지 채널 순서가 다름
train/valid split이 잘못됨
```

이런 오류는 학습을 오래 돌린 뒤 발견하면 시간이 많이 낭비되므로<br> 학습 전에 batch 하나를 꺼내 점검하는 습관이 필요하다

학습 전에 batch shape, dtype, label, device, value range, model forward를 차례대로 확인

## 2. 데이터 파이프라인 디버깅이 중요한 이유

모델 학습이 실패했을 때 원인이 모델 구조라고 생각하기 쉽다<br>
하지만 실제로는 데이터 shape나 label dtype 문제일 때가 많다.

예를 들어 다중 분류에서 `CrossEntropyLoss`를 사용한다면 모델 출력과 label은 보통 다음 형태여야 한다

```
logits shape: (batch_size, num_classes)
target shape: (batch_size,)
target dtype: torch.long
```

이 조건이 맞지 않으면 loss 계산에서 오류가 난다

학습 루프를 실행하기 전에 “첫 batch → 모델 forward → loss 계산”까지 한 번 확인해야 한다

## 3. 첫 batch 검사 함수 만들기

먼저 간단한 DataLoader를 만든다

```python
import torch
from torch.utils.data import TensorDataset, DataLoader

X = torch.randn(64, 10)
y = torch.randint(0, 3, size=(64,), dtype=torch.long)

dataset = TensorDataset(X, y)
loader = DataLoader(dataset, batch_size=16, shuffle=True)
```

이제 첫 batch를 검사하는 함수를 작성한다

```python
def inspect_first_batch(loader):
    """
    DataLoader에서 첫 번째 batch를 꺼내 핵심 정보를 출력합니다.
    """
    batch = next(iter(loader))

    print("batch type:", type(batch))

    # isinstance()는 어떤 값이 특정 자료형의 객체인지 확인하는 함수
    if isinstance(batch, (tuple, list)):
        for i, item in enumerate(batch):
            print(f"batch[{i}] type:", type(item))
            if torch.is_tensor(item):
                print(f"batch[{i}] shape :", item.shape)
                print(f"batch[{i}] dtype :", item.dtype)
                print(f"batch[{i}] device:", item.device)
                print()
    else:
        print(batch)

inspect_first_batch(loader)

# 학습 전에 값 자체도 한 번 확인합니다.
batch_x, batch_y = next(iter(loader))
assert torch.isfinite(batch_x).all(), "입력에 NaN/Inf가 있습니다."
assert torch.isfinite(batch_y.float()).all(), "label에 NaN/Inf가 있습니다."
print("x min/max:", batch_x.min().item(), batch_x.max().item())
print("label counts:", torch.bincount(batch_y))
```
출력
```
batch type: <class 'list'> 또는 <class 'tuple'>
batch[0] shape : torch.Size([16, 10])
batch[0] dtype : torch.float32
batch[0] device: cpu

batch[1] shape : torch.Size([16])
batch[1] dtype : torch.int64
batch[1] device: cpu
```

## 4. 모델 forward까지 한 번에 점검하기

DataLoader batch가 모델에 들어가는지 확인

```python
import torch.nn as nn

model = nn.Linear(10, 3)
criterion = nn.CrossEntropyLoss()

batch_x, batch_y = next(iter(loader))

logits = model(batch_x)
loss = criterion(logits, batch_y)

print("batch_x shape:", batch_x.shape)
print("batch_y shape:", batch_y.shape)
print("logits shape :", logits.shape)
print("loss         :", loss.item())
```
출력
```
batch_x shape: torch.Size([16, 10])
batch_y shape: torch.Size([16])
logits shape : torch.Size([16, 3])
loss         : 1.1772090196609497
```

```
DataLoader batch가 정상인가?
모델 forward가 정상인가?
loss 계산이 정상인가?
```

이 세 가지가 문제없으면 학습 루프를 작성할 준비가 된다

## 5. label shape와 dtype 점검

loss 함수마다 target 조건이 다르다

| 문제 유형 | loss 함수 | 모델 출력 shape | target shape | target dtype |
| --- | --- | --- | --- | --- |
| 회귀 | `MSELoss` | `(N, 1)` 또는 `(N, D)` | 출력과 같음 | `float` |
| 이진 분류 | `BCEWithLogitsLoss` | `(N, 1)` 또는 `(N,)` | 출력과 같음 | `float` |
| 다중 분류 | `CrossEntropyLoss` | `(N, C)` | `(N,)` | `long` |

다중 분류에서 가장 흔한 오류는 label을 float로 만든 경우

```python
# 잘못된 label 예시입니다.
y_wrong = torch.tensor([0.0, 1.0, 2.0, 1.0])
print(y_wrong.dtype)

# 수정합니다.
y_correct = y_wrong.long()
print(y_correct.dtype)
```

`CrossEntropyLoss`에서 class index label은 one-hot이 아니라 class 번호 Tensor인 경우가 많다.<br>
초반 실습에서는 `(batch_size,)` shape의 `torch.long` label을 사용하고,<br> 
class 수가 `C`라면 모든 label이 `0 <= y < C`인지도 확인하세요.

## 6. 이미지 batch 값 범위 확인하기

이미지 데이터에서는 shape뿐 아니라 값의 범위도 확인하면 좋다.

```python
# 더미 이미지 batch입니다.
images = torch.rand(8, 3, 64, 64)
labels = torch.randint(0, 2, size=(8,), dtype=torch.long)

print("images shape:", images.shape)
print("images dtype:", images.dtype)
print("images min:", images.min().item())
print("images max:", images.max().item())
print("labels shape:", labels.shape)
print("labels dtype:", labels.dtype)
```

이미지 transform을 적용한 뒤에는 값 범위가 `[0, 1]`일 수도 있고, Normalize 후에는 `[-1, 1]` 근처가 될 수도 있다.<br>
중요한 것은 의도한 전처리 결과인지 확인하는 것이다

## 7. DataLoader 성능 관련 기초 확인

초반에는 성능 튜닝보다 정확한 동작이 우선입니다. 그래도 다음 옵션을 알고 있으면 좋습니다.

| 옵션 | 의미 |
| --- | --- |
| `batch_size` | 한 번에 묶을 샘플 수 |
| `shuffle` | 데이터를 섞을지 결정 여부 |
| `num_workers` | 데이터를 로딩하는 worker process 수 |
| `pin_memory` | GPU 전송 최적화와 관련된 옵션 |
| `drop_last` | 마지막 작은 batch를 버릴지 결정 여부 |


처음에는 다음처럼 시작해도 충분하다

```python
loader = DataLoader(
    dataset,
    batch_size=32,
    shuffle=True,
    num_workers=0
)
```

이 기초 과정의 기준 환경은 Colab/CPU와 `num_workers=0`이다.<br> 
이 설정에서는 Dataset의 전처리가 main process에서 순서대로 실행되어 디버깅과 재현이 가장 단순하다 <br>
`num_workers>0`은 데이터 로딩 속도가 실제 병목일 때만 별도 실험으로 조정하고, <br>
그때는 worker별 Python/NumPy 난수와 운영체제의 multi-process 실행 규칙도 함께 관리해야 한다.
