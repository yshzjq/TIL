## 1. 이번에 우리가 배울 것

RNN은 이전 정보를 hidden state에 담아 다음 시점으로 넘깁니다. <br>
하지만 시퀀스가 길어지면 초반 정보가 끝까지 잘 전달되지 않을 수 있다.

이 문제를 **장기 의존성(long-term dependency) 문제**라고 한다.

## 2. 장기 의존성이란 무엇인가

장기 의존성은 멀리 떨어진 정보가 현재 예측에 중요한 상황을 말합니다.

예를 들어 문장을 생각해보면

```
나는 어제 도서관에서 빌린 책을 오늘 아침에 드디어 다 읽었다.
```

문장 뒤쪽의 “읽었다”를 해석하려면 앞쪽의 “책”이 중요하다.<br> 
이처럼 앞쪽 정보가 뒤쪽 판단에 영향을 주는 경우가 많다.

RNN은 순서대로 정보를 전달하므로 이론적으로는 앞쪽 정보를 뒤쪽까지 가져갈 수 있다. <br>하지만 실제 학습에서는 시점이 길어질수록 앞쪽 정보의 영향이 약해질 수 있다.

## 3. 경사 소실을 직관적으로 이해하기

학습은 loss에서 시작한 gradient가 뒤로 전달되면서 parameter를 업데이트하는 과정이다

이때 작은 값이 반복해서 곱해지면 점점 더 작아진다.

```
0.5 × 0.5 × 0.5 × 0.5 = 0.0625
```

이렇게 gradient가 앞쪽 시점까지 거의 도달하지 못할 정도로 작아지는 현상을<br> **경사 소실(vanishing gradient)** 이라고 한다

경사 소실은 학습 신호가 멀리 갈수록 희미해지는 현상이라고 생각하면 좋다.<br> 초반 정보가 중요해도, 그 정보를 학습하라는 신호가 충분히 도달하지 않으면 모델이 그 관계를 잘 배우기 어렵다.


## 4. 코드로 반복 곱셈 확인하기

작은 값이 여러 번 곱해질 때 얼마나 빠르게 작아지는지 보여준다


```python
value = 1.0

# 0.5를 반복해서 곱합니다.
# RNN의 실제 gradient 계산을 그대로 구현한 것은 아니지만,
# 경사 소실을 직관적으로 이해하는 데 도움이 됩니다.
for step in range(1, 11):
    value = value * 0.5
    print(f"step={step:2d}, value={value:.8f}")
```

출력

```
step= 1, value=0.50000000
step= 2, value=0.25000000
step= 3, value=0.12500000
...
step=10, value=0.00097656
```

## 5. RNN 학습에서 왜 어려운가요?

RNN은 hidden state를 반복적으로 갱신합니다. 이 반복 구조 때문에 긴 시퀀스에서는 gradient가 여러 단계를 거쳐 전달된다

문제가 되는 상황

1. 초반 시점 정보가 중요하다
2. 하지만 loss는 마지막 시점 근처에서 계산된다
3. gradient가 뒤에서 앞으로 오래 전달된다
4. 중간에 작은 값들이 반복해서 곱해진다
5. 초반 시점까지 도달하는 gradient가 매우 작아진다

결과적으로 모델이 초반 정보를 잘 활용하지 못할 수 있다.

## 6. 경사 폭주와 gradient clipping

반대로 1보다 큰 영향이 반복되면 gradient가 매우 커질 수 있다. <br>
이를 **경사 폭주(exploding gradient)**라고 합니다. <br>
loss가 갑자기 `nan`이 되거나 gradient norm이 비정상적으로 커지는 신호로 나타날 수 있다.


```
1.5 × 1.5 × 1.5 × 1.5 × 1.5 ≈ 7.59
```

학습 코드에서는 `loss.backward()` 다음, `optimizer.step()` 전에 gradient norm을 제한할 수 있다.

```python
import torch
import torch.nn as nn

# clipping 위치를 독립 실행으로 확인할 수 있는 작은 예제
model = nn.Linear(2, 1)

# 지금은 모델을 학습시키는 것이 아니라
# 큰 gradient를 일부러 만들어 clipping을 확인하려는 예제
#
# no_grad()를 사용하면 아래 weight 변경 과정은
# gradient 계산 기록에 포함되지 않는다.
with torch.no_grad():
    # weight 2개를 모두 10으로 설정
    #
    # weight = [10, 10]
    model.weight.fill_(10.0)

    # bias는 0으로 설정
    model.bias.zero_()

# SGD를 사용해서 model의 parameter를 업데이트합니다.
#
# learning rate = 0.01
optimizer = torch.optim.SGD(
    model.parameters(),
     lr=0.01
)


# 샘플 하나가 있고 feature가 2개입니다.
#
# shape = (1, 2)
inputs = torch.tensor([[10.0, 10.0]])

# 이 샘플의 실제 정답은 0이라고 가정합니다.
#
# shape = (1, 1)
labels = torch.tensor([[0.0]])

# 회귀 문제이므로 평균제곱오차(MSE)를 사용
criterion = nn.MSELoss()

optimizer.zero_grad(set_to_none=True)
logits = model(inputs)
loss = criterion(logits, labels)
loss.backward()


# 현재 모든 parameter의 gradient를 모아서
# 전체 gradient의 L2 norm을 계산합니다.
#
# 만약 그 크기가 max_norm=1.0보다 크다면
# gradient의 방향은 유지하면서
# 전체 크기를 1.0 수준으로 줄입니다.
#
# 중요한 순서:
#
# loss.backward()
#      ↓
# gradient clipping
#      ↓
# optimizer.step()
#
# 이어야 합니다.
#
# optimizer.step() 이후에 clipping하면 이미
# 큰 gradient로 parameter를 업데이트한 뒤이므로 늦습니다.
total_norm = torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0
)

# 모든 parameter의 gradient를 제곱해서 더합니다.
#
# L2 norm 계산 과정:
#
# sqrt(g1^2 + g2^2 + g3^2 + ...)
#
# 여기서는 우선 제곱합만 구합니다.
after_sq = sum(
    float((p.grad ** 2).sum())
    for p in model.parameters()
    if p.grad is not None
)

# 제곱합에 제곱근을 취해서
# clipping 이후의 실제 gradient L2 norm을 구합니다.
after_norm = after_sq ** 0.5

optimizer.step()

# clip_grad_norm_()의 반환값은
# "clipping하기 전" gradient의 전체 norm입니다.
print("gradient norm before clipping:", float(total_norm))

# 우리가 직접 계산한
# "clipping 이후" gradient의 전체 norm입니다.
#
# max_norm=1.0으로 설정했기 때문에
# 약 1.0이 나오는 것을 확인할 수 있습니다.
print("gradient norm after clipping :", after_norm)
```

`clip_grad_norm_`의 반환값은 clipping 전 norm이며,<br>
적용 후 norm은 `parameter.grad`에서 다시 계산한다. 

`max_norm=1.0`은 시작 예시일 뿐 모든 문제의 정답은 아니다<br>
clipping은 폭주를 완화하는 안전장치이며, 잘못된 learning rate나 데이터·모델 문제를 대신 해결하지는 않는다.

## 7. 자주 하는 실수

### 실수 1. 경사 소실을 “무조건 RNN이 학습 불가능하다”로 이해하기

경사 소실은 RNN이 긴 시퀀스에서 어려움을 겪을 수 있다는 뜻이지, 모든 RNN이 항상 실패한다는 뜻은 아니다.<br>
짧은 시퀀스나 단순한 패턴에서는 RNN도 충분히 동작할 수 있다.

### 실수 2. loss가 줄어들지 않는데 epoch만 늘리기

장기 의존성 문제나 gradient 문제가 있는 상황에서 epoch만 늘리면 시간이 더 걸릴 뿐 원인이 해결되지 않을 수 있다. 

이럴 때는 sequence length, 모델 구조, learning rate, gradient norm 등을 함께 확인해야 한다
