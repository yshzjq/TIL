## 1. 이번에 우리가 배울 것

매 epoch마다 값을 저장

```
1 epoch -> train_loss, train_acc, valid_loss, valid_acc
2 epoch -> train_loss, train_acc, valid_loss, valid_acc
3 epoch -> train_loss, train_acc, valid_loss, valid_acc
...
```

이렇게 기록해두면 학습이 진행되면서 모델이 좋아지는지, 과적합이 시작되는지, learning rate가 너무 큰지 등을 판단할 수 있다.



## 2. 왜 epoch 로그가 필요한가요?

학습을 한 번 실행하고 마지막 accuracy만 보는 것은 위험하다<br>
마지막 결과가 좋더라도 중간에 validation loss가 이미 증가하고 있었다면 과적합이 진행되었을 수 있다.

| 기록하지 않은 경우 | 기록한 경우 |
| --- | --- |
| 마지막 성능만 확인 | 성능 변화 흐름 확인 |
| 과적합 시작 시점 파악 어려움 | train/valid 차이 확인 가능 |
| 실험 비교 어려움 | 다른 설정과 비교 가능 |
| 재현성 낮음 | 리포트 작성 가능 |

딥러닝 실험은 결과 숫자 하나가 아니라, **결과가 만들어진 과정**까지 함께 기록해야 한다


## 3. history dictionary 만들기

가장 간단한 로그 저장 방식은 Python dictionary에 list를 넣는 것이다

```python
# epoch마다 metric을 append할 빈 history를 만듭니다.
history = {
    "train_loss": [],
    "train_acc": [],
    "valid_loss": [],
    "valid_acc": []
}
```

각 key는 하나의 metric을 의미한다

| key | 의미 |
| --- | --- |
| `train_loss` | train 데이터 기준 평균 loss |
| `train_acc` | train 데이터 기준 accuracy |
| `valid_loss` | validation 데이터 기준 평균 loss |
| `valid_acc` | validation 데이터 기준 accuracy |

## 4. epoch loop에서 metric 저장하기

```python
def fit(model, train_loader, valid_loader, criterion, optimizer, device, epochs):
    """
    여러 epoch 동안 모델을 학습하고 history를 반환합니다.
    """

    # 매 epoch의 결과를 저장할 dictionary입니다.
    history = {
        "train_loss": [],
        "train_acc": [],
        "valid_loss": [],
        "valid_acc": []
    }

    for epoch in range(1, epochs + 1):
        # 1. train 데이터로 한 epoch 학습합니다.
        train_loss, train_acc = train_one_epoch(
            model=model,
            train_loader=train_loader,
            criterion=criterion,
            optimizer=optimizer,
            device=device
        )

        # 2. validation 데이터로 현재 모델 성능을 평가합니다.
        valid_loss, valid_acc = validate(
            model=model,
            valid_loader=valid_loader,
            criterion=criterion,
            device=device
        )

        # 3. 계산된 metric을 history에 저장합니다.
        history["train_loss"].append(train_loss)
        history["train_acc"].append(train_acc)
        history["valid_loss"].append(valid_loss)
        history["valid_acc"].append(valid_acc)

        # 4. 현재 epoch 결과를 화면에 출력합니다.
        print(
            f"Epoch [{epoch:03d}/{epochs:03d}] "
            f"train_loss={train_loss:.4f} "
            f"train_acc={train_acc:.4f} "
            f"valid_loss={valid_loss:.4f} "
            f"valid_acc={valid_acc:.4f}"
        )

    return history
```
`epoch:03d`는 epoch 숫자를 세 자리로 표시하겠다는 뜻.

1은 `001`, 12는 `012`로 출력

## 5. 로그를 보기 좋게 출력하기

학습 로그는 짧고 일정한 형식이 좋다.

```
[읽기용 코드 조각]
print(
    f"Epoch [{epoch:03d}/{epochs:03d}] "
    f"train_loss={train_loss:.4f} "
    f"train_acc={train_acc:.4f} "
    f"valid_loss={valid_loss:.4f} "
    f"valid_acc={valid_acc:.4f}"
)
```
출력 예시

```
Epoch [001/010] train_loss=1.0842 train_acc=0.4219 valid_loss=1.0215 valid_acc=0.5100
Epoch [002/010] train_loss=0.9731 train_acc=0.5625 valid_loss=0.9420 valid_acc=0.5900
Epoch [003/010] train_loss=0.8817 train_acc=0.6500 valid_loss=0.9112 valid_acc=0.6200
```

로그에서 확인할 것은 단순히 숫자가 높은지 낮은지가 아니다

- train loss가 줄어드는가?
- valid loss도 함께 줄어드는가?
- train acc와 valid acc 차이가 너무 커지지 않는가?
- 어느 epoch부터 valid 성능이 멈추는가?


## 6. loss curve 그리기

`history`에 저장된 loss를 그래프로 그리기

```python
import matplotlib.pyplot as plt

def plot_loss(history):
    """
    train loss와 validation loss를 한 그래프에 표시합니다.
    """

    # epoch 번호를 1부터 시작하도록 만듭니다.
    epochs = range(1, len(history["train_loss"]) + 1)

    plt.figure(figsize=(8, 5))

    # train loss 곡선입니다.
    plt.plot(epochs, history["train_loss"], label="train_loss")

    # validation loss 곡선입니다.
    plt.plot(epochs, history["valid_loss"], label="valid_loss")

    # 그래프 제목과 축 이름을 지정합니다.
    plt.title("Loss Curve")
    plt.xlabel("Epoch")
    plt.ylabel("Loss")

    # 범례를 표시합니다.
    plt.legend()

    # 격자를 표시하면 변화 흐름을 읽기 쉽습니다.
    plt.grid(True)

    plt.show()
```



## 7. accuracy curve 그리기

accuracy도 같은 방식으로 시각화한다

```python
def plot_accuracy(history):
    """
    train accuracy와 validation accuracy를 한 그래프에 표시합니다.
    """

    epochs = range(1, len(history["train_acc"]) + 1)

    plt.figure(figsize=(8, 5))
    plt.plot(epochs, history["train_acc"], label="train_acc")
    plt.plot(epochs, history["valid_acc"], label="valid_acc")

    plt.title("Accuracy Curve")
    plt.xlabel("Epoch")
    plt.ylabel("Accuracy")
    plt.legend()
    plt.grid(True)
    plt.show()

# 두 함수를 정의한 뒤 실제로 호출해야 그래프가 표시됩니다.
plot_loss(history)
plot_accuracy(history)
```

점선은 valid loss가 가장 낮았던 16 epoch를 표시

제목의 final test=1.000은 모델 선택을 마친 뒤 test set을 한 번 평가한 결과

환경에 따라 숫자는 조금 달라질 수 있으므로 곡선의 방향과 간격을 중심으로 읽는다

두 그래프에서 train과 valid 곡선의 방향과 간격을 함께 본다<br>
초반에는 둘 다 좋아지다가 train만 계속 좋아지고 valid loss가 오르기 시작하면 과적합 신호로 해석할 수 있다.

| 패턴 | 해석 |
| --- | --- |
| train/valid accuracy가 함께 상승 | 일반적으로 좋은 흐름 |
| train accuracy만 상승 | 과적합 가능성 |
| 둘 다 낮음 | 과소적합 또는 학습 부족 가능성 |
| 값이 심하게 출렁임 | learning rate, 데이터, batch size 확인 필요 |

## 8. 자주 하는 실수

### 실수 1. history를 epoch loop 안에서 새로 만드는 경우

```
[읽기용 코드 조각]
for epoch in range(epochs):
    # 잘못된 예시입니다.
    # 매 epoch마다 history가 초기화됩니다.
    history = {"train_loss": [], "valid_loss": []}
```

`history`는 epoch loop 바깥에서 한 번만 만들어야 한다.

### 실수 2. train과 valid metric 이름을 섞는 경우

```
[읽기용 코드 조각]
# 잘못된 예시입니다.
history["valid_loss"].append(train_loss)
```

metric 이름과 저장하는 값을 반드시 맞춘다

### 실수 3. 그래프만 보고 결론을 과하게 내리는 경우

그래프는 실험을 해석하는 도구다. 하지만<br> 
한 번의 실험 결과만으로 “이 모델이 항상 좋다”고 결론 내리면 안 된다<br>
seed, 데이터 분할, epoch 수, learning rate를 함께 확인해야 한다
