## 1. 이번에 우리가 배울 것

모델이 예측값을 출력하면 모델이 얼마나 잘 맞혔는지 어떻게 숫자로 판단하는 역할을 하는 것이 **손실 함수(loss function)**다.

손실 함수는 모델의 예측값과 실제 정답을 비교해 **틀린 정도를 숫자 하나로** 만들어준다. 

이 숫자를 줄이는 방향으로 parameter를 업데이트하는 것이 딥러닝 학습의 기본 흐름이다.

<img src="{{ '/assets/images/uploads/deep-learning/손실 함수와 목표 함수 흐름.png' | relative_url }}" alt="손실 함수와 목표 함수 흐름.png" loading="lazy">

모델 예측과 정답이 손실 함수로 들어가 scalar loss가 된다.<br> 이어서 `loss.backward()`가 gradient를 계산하고, optimizer의 `step()`이 그 gradient를 사용해 parameter를 업데이트한다.

## 2. 손실 함수는 왜 필요한가요?

### 2-1. 정답/오답만으로는 왜 부족한가요?

다음 두 예측은 모두 틀렸지만 틀린 정도가 다르다.

```
집값 정답: 3.5억
모델 A 예측: 3.4억 -> 차이 0.1억
모델 B 예측: 1.0억 -> 차이 2.5억
```

두 예측을 똑같이 “오답”으로만 처리하면 모델 A가 정답에 훨씬 가깝다는 정보를 잃는다.<br>
손실 함수는 이 차이를 연속적인 숫자로 만들어 더 나은 예측과 더 나쁜 예측을 구분한다

분류도 마찬가지다

```
정답 class 확률 0.49 -> 아슬아슬하게 틀림
정답 class 확률 0.01 -> 매우 자신 있게 틀림
```

두 경우에 같은 벌점을 주기보다, <br>
정답 class에 거의 근거를 주지 않은 두 번째 예측에 더 큰 벌점을 주는 편이 학습에 유용하다

### 2-2. loss function과 objective function은 같은 말인가요?

기초 단계에서는 거의 같은 의미로 사용해도 된다, 조금 더 엄밀히 구분하면

```
loss: 한 샘플 또는 한 batch의 예측 오차
objective: 학습에서 최종적으로 최소화할 전체 식
```

objective에는 데이터 loss뿐 아니라 규제 항이 추가될 수도 있다.

```
objective = data_loss + lambda * regularization
```

손실 함수는 “틀렸는가”를 넘어 “얼마나, 어떤 방향으로 틀렸는가”를 미분 가능한 숫자로 표현한다.

모델은 학습 초기에 대부분 틀린다. 중요한 것은 단순히 틀렸다는 사실이 아니라, **얼마나 틀렸는지**를 계산하는 것이다.


예를 들어 집값을 예측하는 회귀 문제를 보면

```
모델 예측값: 3.2억
실제 정답값: 3.5억
차이: 0.3억
```

이 차이를 그냥 둘 수도 있지만, 학습에서는 보통 차이를 제곱하거나 평균을 내서 하나의 loss 값으로 만듭니다.

```
loss가 크다  -> 많이 틀렸다
loss가 작다  -> 덜 틀렸다
loss가 0에 가깝다 -> 거의 맞혔다
```

딥러닝 학습의 목표는 loss를 한 번 계산하는 것이 아니라, 여러 step 동안 loss가 줄어들도록 parameter를 업데이트하는 것


## 3. prediction, target, loss의 관계

손실 함수에는 보통 두 가지가 들어간다

| 이름 | 의미 |
| --- | --- |
| prediction 또는 output | 모델이 출력한 값 |
| target 또는 label | 실제 정답 |


회귀 문제에서 예측값과 정답값은 보통 같은 shape를 가진다
```python
import torch

# 모델 예측값이라고 가정합니다.
pred = torch.tensor([[2.5], [3.0], [4.0]])

# 실제 정답값입니다.
target = torch.tensor([[3.0], [2.0], [5.0]])

print("pred shape  :", pred.shape)
print("target shape:", target.shape)
```

출력

```
pred shape  : torch.Size([3, 1])
target shape: torch.Size([3, 1])
```

## 4. `MSELoss`를 직접 계산해보기

회귀 문제에서 가장 기본적으로 배우는 loss는 **MSELoss(Mean Squared Error Loss)**다.

MSE는 다음 순서로 계산

```
1. 예측값 - 정답값
2. 차이를 제곱
3. 전체 평균
```

```python
import torch
import torch.nn as nn

pred = torch.tensor([[2.5], [3.0], [4.0]])
target = torch.tensor([[3.0], [2.0], [5.0]])

# 1. 예측값과 정답값의 차이를 계산합니다.
error = pred - target

# 2. 차이를 제곱합니다.
squared_error = error ** 2

# 3. 제곱 오차의 평균을 계산합니다.
manual_mse = squared_error.mean()

# PyTorch MSELoss와 비교합니다.
criterion = nn.MSELoss()
torch_mse = criterion(pred, target)

print("error:")
print(error)
print("squared_error:")
print(squared_error)
print("manual_mse:", manual_mse)
print("torch_mse :", torch_mse)
print("same?", torch.allclose(manual_mse, torch_mse))
```

출력은 다음과 같습니다.

```
error:
tensor([[-0.5000],
        [ 1.0000],
        [-1.0000]])
squared_error:
tensor([[0.2500],
        [1.0000],
        [1.0000]])
manual_mse: tensor(0.7500)
torch_mse : tensor(0.7500)
same? True
```

제곱 오차의 합 2.25를 원소 3개로 나누면 MSE는 0.75 가 나온다

## 5. reduction 옵션 이해하기

reduction은 여러 개의 오차를 한 개의 batch loss로 어떻게 묶을지 정합니다.


### 5-1. 샘플별 loss와 batch loss를 구분합니다

샘플 세 개의 제곱 오차가 있으면

```
sample 1 loss = 0.25
sample 2 loss = 1.00
sample 3 loss = 1.00
```

`reduction='none'`은 세 값을 그대로 유지하고. `'sum'`은 `2.25`, `'mean'`은 `0.75`를 반환합니다.

```
none -> [0.25, 1.00, 1.00]
sum  -> 2.25
mean -> 0.75
```

### 5-2. 왜 기본 학습에서는 mean을 많이 사용하나요?

mean은 batch 안의 원소 수로 나누므로 batch size가 달라져도 loss와 gradient 규모가 비교적 일관되게 유지된다

예를 들어 같은 패턴의 데이터를 두 배 복제하면 다음과 같다

```
sum loss  -> 데이터 수가 두 배면 약 두 배
mean loss -> 같은 분포라면 비슷한 규모
```

따라서 batch size를 바꿨을 때 learning rate와 gradient 규모가 불필요하게 크게 달라지는 것을 줄일 수 있다

### 5-3. `none`은 언제 사용하나요?

- 어떤 샘플의 오차가 큰지 찾을 때
- 샘플별 가중치를 적용할 때
- hard example mining이나 error analysis를 할 때

```python
per_sample_loss = nn.MSELoss(reduction='none')(pred, target)
per_sample_loss = per_sample_loss.view(per_sample_loss.shape[0], -1).mean(dim=1)
print("sample losses:", per_sample_loss)
```

`reduction='none'`의 출력은 여러 원소를 가진 Tensor이므로 그대로 `backward()`하려면 
<br>
각 원소의 가중치를 알려주거나, 다시 `mean()` 또는 `sum()`으로 scalar를 만들어야 합니다.



PyTorch loss 함수는 보통 `reduction` 옵션을 가진다

| reduction | 의미 |
| --- | --- |
| `'none'` | 각 원소별 loss를 그대로 반환합니다. |
| `'mean'` | 평균 loss를 반환합니다. 기본값입니다. |
| `'sum'` | 합계 loss를 반환합니다. |


```python
import torch
import torch.nn as nn

pred = torch.tensor([[2.5], [3.0], [4.0]])
target = torch.tensor([[3.0], [2.0], [5.0]])

loss_none = nn.MSELoss(reduction='none')(pred, target)
loss_mean = nn.MSELoss(reduction='mean')(pred, target)
loss_sum = nn.MSELoss(reduction='sum')(pred, target)

print("loss_none:")
print(loss_none)
print("loss_mean:", loss_mean)
print("loss_sum :", loss_sum)
```

출력은 다음과 같습니다.

```
loss_none:
tensor([[0.2500],
        [1.0000],
        [1.0000]])
loss_mean: tensor(0.7500)
loss_sum : tensor(2.2500)
```

`loss_none`은 각 샘플 또는 각 원소의 loss를 확인할 때 유용하다<br> 
학습 루프에서는 기본값 `reduction='mean'`으로 만든 scalar loss를 사용한다 <br>

## 6. loss는 작을수록 좋은 목표 함수다

### 6-1. 서로 다른 loss의 숫자를 직접 비교하지 않습니다

`MSELoss=0.1`과 `CrossEntropyLoss=0.5`만 보고 첫 모델이 더 좋다고 말할 수 없다. 문제와 단위, loss 정의가 다르기 때문이다

```
같은 실험의 train loss 추세 비교 -> 의미 있음
서로 다른 loss 함수의 절대값 비교 -> 의미 없음
```


### 6-2. loss가 매 step 반드시 내려가야 할까?

mini-batch마다 포함된 샘플 난이도가 다르고 optimizer update도 완벽하지 않으므로 한두 step에서는 loss가 오를 수 있습니다.

```
3.2 -> 2.8 -> 2.9 -> 2.4 -> 2.2
```

중간에 `2.8 -> 2.9`로 올랐지만 전체 추세는 내려가고 있다<br>
한 점보다 이동 평균, epoch 평균, validation loss를 함께 봅니다.

### 6-3. loss와 metric은 왜 다를 수 있나요?

분류 모델의 class 예측은 argmax나 threshold처럼 불연속적인 결정을 사용한다. 확률이 조금 좋아져도 label이 바뀌지 않으면 accuracy는 그대로일 수 있다.

```
정답 class 확률: 0.51 -> 0.80
예측 label: 둘 다 정답
accuracy: 변화 없음
CrossEntropyLoss: 감소
```

반대로 accuracy가 같아도 틀린 샘플에 얼마나 자신 있었는지에 따라 loss는 다를 수 있다

학습에는 loss, 모델 선택에는 validation loss와 업무 metric을 함께 사용된다

---

딥러닝에서는 loss를 **목표 함수(objective function)**로 보고, 이 값을 줄이는 방향으로 학습합니다.

```
좋은 parameter -> 예측이 정답에 가까움 -> loss가 작음
나쁜 parameter -> 예측이 정답과 멂 -> loss가 큼
```

하지만 loss가 항상 단조롭게 줄어드는 것은 아니다. mini-batch마다<br> 데이터가 다르고 optimizer가 조금씩 parameter를 바꾸기 때문에 loss는 흔들리면서 감소할 수 있다


loss를 볼 때 한 step 값 하나만 보고 판단하지 말고, 여러 step 또는 epoch 동안의 흐름을 봐야 한다.<br>
서로 다른 loss 함수, target 단위, reduction 방식을 사용한 숫자는 크기만 보고 직접 비교하면 안된다.

교안 초반에는 둘을 같은 학습 목표처럼 사용합니다. 엄밀히는 데이터에 대한 loss에 regularization 항 등을 더한 전체 최적화 식을 objective라고 부르기도 합니다. 예를 들어 `objective = data_loss + λ * regularization`처럼 구성할 수 있다.


## 7. loss만 계산하면 학습이 되나요?

다음 세 단계를 분리해 이해하세요.

| 단계 | 코드 | 역할 |
| --- | --- | --- |
| 채점 | `loss = criterion(pred, target)` | 현재 예측이 얼마나 틀렸는지 계산 |
| 원인 분석 | `loss.backward()` | parameter별 gradient 계산 |
| 실제 수정 | `optimizer.step()` | gradient를 사용해 weight와 bias 변경 |

### 7-1. backward만 하면 parameter가 바뀌지 않는다

```python
weight_before = model.weight.detach().clone()
loss.backward()
weight_after_backward = model.weight.detach().clone()
print(torch.equal(weight_before, weight_after_backward))  # True
```

### 7-2. step을 호출하기 전에 새 gradient가 계산되어 있어야 한다

새 gradient가 계산되어 있어야 합니다. `step()`은 optimizer가 현재 `.grad`를 읽어 parameter를 바꾸는 단계다

```
loss 계산만 함      -> parameter 변화 없음
backward까지 함     -> gradient 생성, parameter 변화 없음
step까지 함         -> parameter 실제 변화
```

### 7-3. `detach().clone()`은 왜 사용하나요?

`model.weight`를 그대로 저장하면 같은 parameter 객체를 계속 바라볼 수 있습니다.<br> 
업데이트 전 값을 독립적으로 보관하려면 계산 그래프에서 분리하고 복사합니다.

```python
weight_before = model.weight.detach().clone()
```

loss는 채점표, backward는 수정 방향 계산, step은 실제 답안 수정

학습 진행 순서

```
1. 모델이 예측합니다.
2. loss를 계산합니다.
3. loss.backward()로 gradient를 계산합니다.
4. optimizer.step()으로 parameter를 업데이트합니다.
```

아래 코드는 loss만 계산하는 예시

```python
import torch
import torch.nn as nn

model = nn.Linear(1, 1)
criterion = nn.MSELoss()

x = torch.tensor([[1.0], [2.0], [3.0]])
y = torch.tensor([[2.0], [4.0], [6.0]])

pred = model(x)
loss = criterion(pred, y)

print("loss:", loss)
```

이 코드는 loss를 계산하지만 parameter를 업데이트하지 않는다
