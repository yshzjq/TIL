## 1. 이번에 우리가 배울 것

딥러닝 학습은 단순히 `loss`가 한 번 낮아졌다고 끝나는 과정이 아니다.<br>
epoch가 반복되면서 train loss와 validation loss가 어떤 방향으로 움직이는지 봐야 한다

```
train loop 실행
-> epoch별 train loss 저장
-> epoch별 valid loss 저장
-> 곡선으로 시각화
-> 과적합/과소적합/불안정 학습 판단
```

곡선 해석과 model/hyperparameter 선택에는 train·valid만 사용하고, test set은 모든 선택이 끝난 뒤 최종 성능을 한 번 확인할 때 사용<br>
한 번의 seed 결과만으로 일반화하지 말고, 가능하면 여러 seed에서 같은 경향이 반복되는지도 확인

train loss는 계속 내려가는데 validation loss가 다시 올라가기 시작하면 과적합 가능성을 의심

## 2. 왜 학습 곡선을 봐야 하나


모델 학습이 끝났을 때 accuracy 하나만 보면 많은 정보를 놓친다<br>
예를 들어 최종 validation accuracy가 82%라고 해도 다음 상황들은 서로 다르다

## 3. train loss와 validation loss

`train loss`는 학습 데이터에서 계산한 loss다. 모델은 이 값을 줄이기 위해 파라미터를 업데이트한다

`validation loss`는 검증 데이터에서 계산한 loss다. 검증 데이터는 파라미터 업데이트에 직접 사용하지 않는다

```
train loss      : 모델이 공부한 문제에서의 오답 정도
validation loss : 모델이 처음 보는 문제에서의 오답 정도
```


모델을 평가할 때는 train loss보다 validation loss가 더 중요하ㄷ<br> 실제로는 모델이 외운 데이터가 아니라 처음 보는 데이터에서 잘 동작해야 하기 때문입니다.

## 4. 좋은 학습 곡선의 기본 패턴

좋은 학습 곡선은 보통 다음 패턴을 가진다.

1. 초반에는 train loss와 validation loss가 함께 감소합니다.
2. 어느 시점부터 validation loss 감소 속도가 느려집니다.
3. train loss와 validation loss 사이의 차이가 너무 커지지 않습니다.
4. accuracy는 train과 validation에서 함께 올라갑니다.

```
좋은 패턴
train loss ↓
valid loss ↓
train acc ↑
valid acc ↑
```

물론 실제 학습 곡선은 매끄럽지 않을 수 있다. <br>
batch sampling, learning rate, 데이터 크기 때문에 epoch마다 조금씩 흔들릴 수 있다.


## 5. 위험 신호를 읽는 방법

다음 패턴이 보이면 학습 설정을 다시 확인해야 한다

| 곡선 패턴 | 의심할 수 있는 문제 | 먼저 확인할 것 |
| --- | --- | --- |
| train loss만 계속 감소하고 valid loss는 증가 | 과적합 | Dropout, weight decay, Early Stopping |
| train/valid loss가 모두 높고 거의 줄지 않음 | 과소적합 | 모델 크기, learning rate, epoch 수 |
| loss가 크게 출렁임 | 불안정 학습 | learning rate, batch size |
| validation accuracy가 이상하게 높음 | 데이터 누수 가능성 | train/valid split, 중복 샘플 |


validation 성능이 train 성능보다 훨씬 높게 나오면 무조건 좋은 것이 아니다.<br>
데이터 분할이 잘못되었거나, validation 데이터가 너무 쉬운 경우도 있다.

또한 학습 loop에서 기록한 train metric과 epoch 뒤의 valid metric은 조건이 다를 수 있습니다.<br> 
train metric은 weight가 batch마다 바뀌는 동안 `model.train()`과 랜덤 augmentation 상태에서 누적되고,<br>
valid metric은 한 epoch의 학습이 끝난 뒤, 마지막 batch까지 업데이트된 모델을 model.eval() 모드로 전환하고,<br> 파라미터를 더 이상 업데이트하지 않은 상태에서 계산한다.<br>

**일반화 gap(generalization gap)**은 동일한 모델을 같은 평가 조건에서 측정했을 때 나타나는 train 성능과 validation 성능의 차이입니다.

학습 중에 기록한 train metric은 랜덤 증강과 model.train()이 적용되고, batch마다 모델의 파라미터가 변경되는 과정에서 계산되므로 valid metric과 측정 조건이 다릅니다.

따라서 한 epoch의 학습이 끝나면 랜덤 증강이 없는 평가용 train loader를 사용하여 train set을 다시 평가합니다. 이때 모델을 model.eval() 모드로 전환하고 torch.no_grad()를 사용하며, 추가적인 학습이나 파라미터 업데이트는 수행하지 않는다

이렇게 동일한 마지막 모델과 동일한 평가 조건으로 측정한 train metric과 valid metric을 비교하면 일반화 gap을 더 공정하게 확인할 수 있다.

## 6. epoch 로그 저장 구조 만들기

학습 곡선을 그리려면 epoch마다 loss와 accuracy를 저장해야 한다

```python
# epoch별 학습 결과를 저장할 빈 리스트를 만듭니다.
# 각 리스트에는 epoch가 끝날 때마다 숫자 하나씩 추가됩니다.
history = {
    "train_loss": [],  # 각 epoch의 train 평균 loss
    "valid_loss": [],  # 각 epoch의 validation 평균 loss
    "train_acc": [],   # 각 epoch의 train accuracy
    "valid_acc": []    # 각 epoch의 validation accuracy
}

# 예시 로그입니다.
# 실제 학습에서는 train_one_epoch(), validate() 함수의 반환값을 여기에 넣습니다.
history["train_loss"].append(0.82)
history["valid_loss"].append(0.91)
history["train_acc"].append(0.70)
history["valid_acc"].append(0.66)
```

여기서 중요한 점은 **한 epoch가 끝날 때마다 같은 순서로 값을 추가**하는 것이다

## 7. loss curve 시각화하기

아래 함수는 `history`에 저장된 loss를 그래프로 그린다.

```python
import matplotlib.pyplot as plt

def plot_loss_curves(history):
    """
    train loss와 validation loss를 한 그래프에 그리는 함수입니다.

    history:
        epoch별 metric이 저장된 딕셔너리입니다.
        반드시 "train_loss", "valid_loss" 키를 가지고 있어야 합니다.
    """

    # epoch 번호를 만듭니다.
    # history["train_loss"] 길이가 5라면 epoch는 [1, 2, 3, 4, 5]가 됩니다.
    epochs = range(1, len(history["train_loss"]) + 1)

    # 그래프 크기를 지정합니다.
    # 노션이나 Colab에서 너무 작게 보이지 않도록 적당히 키웁니다.
    plt.figure(figsize=(8, 5))

    # train loss 곡선을 그립니다.
    plt.plot(epochs, history["train_loss"], marker="o", label="train_loss")

    # validation loss 곡선을 그립니다.
    plt.plot(epochs, history["valid_loss"], marker="o", label="valid_loss")

    # 그래프 제목과 축 이름을 붙입니다.
    plt.title("Loss Curves")
    plt.xlabel("Epoch")
    plt.ylabel("Loss")

    # 범례와 격자를 표시합니다.
    plt.legend()
    plt.grid(True)

    # 그래프를 화면에 출력합니다.
    plt.show()
```

## 8. accuracy curve 시각화하기

loss만 보면 모델이 실제로 얼마나 맞히는지 알기 어렵다. 분류 문제에서는 accuracy도 함께 보는 것이 좋다.

```python
def plot_accuracy_curves(history):
    """
    train accuracy와 validation accuracy를 한 그래프에 그리는 함수입니다.
    """

    # x축으로 사용할 epoch 번호를 만듭니다.
    epochs = range(1, len(history["train_acc"]) + 1)

    # 그래프 크기를 지정합니다.
    plt.figure(figsize=(8, 5))

    # train accuracy 곡선을 그립니다.
    plt.plot(epochs, history["train_acc"], marker="o", label="train_acc")

    # validation accuracy 곡선을 그립니다.
    plt.plot(epochs, history["valid_acc"], marker="o", label="valid_acc")

    # 그래프 제목과 축 이름을 붙입니다.
    plt.title("Accuracy Curves")
    plt.xlabel("Epoch")
    plt.ylabel("Accuracy")

    # accuracy는 보통 0~1 사이 값이므로 y축 범위를 지정하면 보기 좋습니다.
    plt.ylim(0, 1)

    # 범례와 격자를 표시합니다.
    plt.legend()
    plt.grid(True)

    # 그래프를 화면에 출력합니다.
    plt.show()
```

## 9. 자주 하는 실수

### 실수 1. 마지막 batch 크기를 고려하지 않고 loss를 평균냅니다

batch마다 `loss.item()`을 그냥 평균내면 마지막 batch 크기가 다를 때 정확한 전체 평균이 아닐 수 있다.

```
# 권장 방식입니다.
# batch 평균 loss에 batch_size를 곱해서 샘플 기준 loss 합으로 바꾼다
total_loss += loss.item() * batch_size
```

### 실수 2. train loss와 valid loss를 같은 데이터에서 계산합니다

train 데이터와 validation 데이터가 섞이면 일반화 성능을 제대로 알 수 없다

```
잘못된 구조: train_loader로 train loss도 계산하고 valid loss도 계산
올바른 구조: train_loader와 valid_loader를 분리
```

### 실수 3. validation 단계에서 `model.eval()`을 호출하지 않는다

Dropout과 BatchNorm이 들어간 모델은 `train()`과 `eval()`에서 동작이 다릅니다. validation에서는 반드시 `model.eval()`을 호출해야 한다

### 실수 4. 학습 중 누적한 train metric과 valid metric을 그대로 같은 조건이라고 생각합니다

정밀한 일반화 gap이 필요하면 epoch 마지막 weight를 eval mode로 고정하고, 랜덤 증강이 없는 평가용 train loader로 train metric을 다시 계산해야한다.
