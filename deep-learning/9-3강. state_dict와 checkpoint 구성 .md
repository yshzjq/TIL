학습한 모델을 저장하려면 모델 객체 전체를 저장하는 것보다, 모델의 학습된 파라미터를 담은 state_dict를 저장하는 방식을 주로 사용한다

inference를 위해 모델을 저장할 때는 학습된 파라미터만 저장하면 되고, `model.state_dict()`를 `torch.save()`로 저장하는 방식이 가장 유연하다

## 2. state_dict란 무엇인가요?

`state_dict`는 PyTorch 모델이나 optimizer의 상태를 담은 Python dictionary입니다.

모델의 `state_dict`에는 학습 가능한 parameter와 등록된 persistent buffer가 들어 있다<br>
예를 들어 `nn.Linear`의 weight·bias와 BatchNorm의 running mean·variance가 포함됩니다.

optimizer의 `state_dict`에는 optimizer가 학습 중 관리하는 상태와 hyperparameter가 들어 있다.
Adam optimizer라면 momentum과 관련된 내부 값도 저장될 수 있다.

| 객체 | state_dict |
| --- | --- |
| model | weight, bias, BatchNorm running mean/var 등 |
| optimizer | learning rate, momentum, Adam 내부 상태 등 |


## 3. model.state_dict 확인

간단한 MLP를 만들고 `state_dict`를 확인
```python
import torch
import torch.nn as nn

class SimpleMLP(nn.Module):
    def __init__(self, input_dim=4, hidden_dim=32, num_classes=3):
        super().__init__()
        self.fc1 = nn.Linear(input_dim, hidden_dim)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_dim, num_classes)

    def forward(self, x):
        x = self.fc1(x)
        x = self.relu(x)
        logits = self.fc2(x)
        return logits

model = SimpleMLP()

# model.state_dict()는 parameter 이름과 Tensor를 담은 dictionary입니다.
model_state = model.state_dict()

for name, tensor in model_state.items():
    print(name, tensor.shape)
```
예상 출력은 다음과 비슷합니다.

```
fc1.weight torch.Size([32, 4])
fc1.bias torch.Size([32])
fc2.weight torch.Size([3, 32])
fc2.bias torch.Size([3])
```

`state_dict`는 모델 구조 자체가 아니라, 모델 안의 parameter 값을 담고 있다. <br>불러올 때는 같은 구조의 모델 클래스를 먼저 만든 뒤 값을 넣어야 한다.

## 4. optimizer.state_dict 확인하기

optimizer도 상태를 가지고 있다.

```python
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

optimizer_state = optimizer.state_dict()

print(optimizer_state.keys())
print(optimizer_state["param_groups"])
```

처음에는 아직 학습을 하지 않았기 때문에 optimizer의 내부 state가 비어 있을 수 있다.<br>
학습이 진행되면 Adam의 moving average 같은 내부 값이 저장됩니다.

**Moving average(이동평균)**는 지금까지 관찰한 값들을 일정 비율로 섞어서 전체적인 흐름을 부드럽게 나타내는 값

gradient의 최근 흐름을 다음 두 값으로 기억

1. Gradient의 이동평균 m
gradient가 주로 어느 방향으로 향하는가?

2. Gradient 제곱의 이동평균 v
gradient의 크기가 최근에 얼마나 컸는가?

m: 어느 방향으로 이동할지 판단
v: 얼마나 크게 이동할지 조절

## 5. 추론용 저장과 학습 재개용 저장의 차이

저장 목적에 따라 필요한 정보가 달라진다

| 목적 | 필요한 정보 |
| --- | --- |
| 추론만 하기 | model_state_dict와 모델 구조를 다시 만들 config |
| 일반적인 학습 재개 | model, optimizer, completed_epochs, history, best metric, 핵심 config |
| 완료된 epoch 경계에서 정확히 재개 | 일반 재개 항목 + Python/NumPy/PyTorch CPU·CUDA 난수 상태 + DataLoader generator 상태 + 사용 중인 EarlyStopping 상태 |

completed_epochs를 모든 batch 처리와 history 기록까지 끝난 epoch 수로 정의한다

예를 들어 5개 epoch를 모두 마친 뒤 저장했다면 completed_epochs=5이고, 로드한 뒤에는 6번째 epoch부터 시작한다

정확한 재개용 checkpoint는 반드시 epoch 전체가 끝나고 history를 갱신한 뒤 저장, epoch 도중 중단된 경우에는 해당 미완료 epoch를 처음부터 다시 실행한다

## 6. checkpoint dictionary 만들기

난수 상태도 `weights_only=True`로 안전하게 불러올 수 있도록 NumPy 배열을 기본 자료형인 list로 바꿔 저장한다

```python
import random
import numpy as np
import torch

def capture_rng_state():
    numpy_state = np.random.get_state()

    return {
        "python": random.getstate(),
        "numpy": {
            "bit_generator": numpy_state[0],
            "state": numpy_state[1].tolist(),
            "pos": int(numpy_state[2]),
            "has_gauss": int(numpy_state[3]),
            "cached_gaussian": float(numpy_state[4]),
        },
        "torch_cpu": torch.get_rng_state(),
        "torch_cuda": (
            torch.cuda.get_rng_state_all()
            if torch.cuda.is_available()
            else None
        ),
    }

loader_generator = torch.Generator().manual_seed(42)
history = {
    "train_loss": [0.9, 0.7, 0.5],
    "valid_loss": [1.0, 0.8, 0.6],
}
config = {
    "model_name": "SimpleMLP",
    "input_dim": 4,
    "hidden_dim": 32,
    "num_classes": 3,
    "learning_rate": 0.001,
    "batch_size": 16,
    "seed": 42,
}

checkpoint = {
    "completed_epochs": 3,
    "model_state_dict": model.state_dict(),
    "optimizer_state_dict": optimizer.state_dict(),
    "best_valid_loss": 0.6,
    "history": history,
    "config": config,
    "rng_state": capture_rng_state(),
    "loader_generator_state": loader_generator.get_state(),
    # EarlyStopping을 사용하지 않는 실험이므로 None입니다.
    "early_stopping_state_dict": None,
}

print(checkpoint.keys())
```

checkpoint에는 “현재 모델 값”뿐 아니라 다음 epoch를 같은 상태에서 시작하는 데 필요한 정보가 함께 들어 있다

## 7. checkpoint 저장 함수 만들기

저장 도중 프로그램이 중단되어 기존 checkpoint가 손상되는 위험을 줄이기 위해 같은 폴더의 임시 파일에 먼저 저장한 뒤 교체한다

```python
from pathlib import Path
import torch

def save_checkpoint(
    model,
    optimizer,
    completed_epochs,
    best_valid_loss,
    history,
    config,
    loader_generator,
    path,
    early_stopper=None,
):
    """완료된 epoch 경계의 학습 상태를 checkpoint로 저장합니다."""

    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)

    checkpoint = {
        "completed_epochs": int(completed_epochs),
        "model_state_dict": model.state_dict(),
        "optimizer_state_dict": optimizer.state_dict(),
        "best_valid_loss": float(best_valid_loss),
        "history": history,
        "config": config,
        "rng_state": capture_rng_state(),
        "loader_generator_state": loader_generator.get_state(),
        "early_stopping_state_dict": (
            early_stopper.state_dict()
            if early_stopper is not None
            else None
        ),
    }

    temporary_path = path.with_suffix(path.suffix + ".tmp")
    torch.save(checkpoint, temporary_path)
    temporary_path.replace(path)

    print(f"checkpoint saved to: {path}")
```

사용 예시

```python
save_checkpoint(
    model=model,
    optimizer=optimizer,
    completed_epochs=3,
    best_valid_loss=0.6,
    history=history,
    config=config,
    loader_generator=loader_generator,
    path="runs/exp001/checkpoints/last.pt",
)
```

출력

```
checkpoint saved to: runs/exp001/checkpoints/last.pt
```

## 8. 자주 하는 실수

### 실수 1. 모델 전체를 무조건 저장하는 경우

```python
# 가능은 하지만 구조 변경에 취약할 수 있습니다.
torch.save(model, "model.pt")
```

처음에는 `state_dict`를 저장하는 방식을 기본으로 사용

```python
torch.save(model.state_dict(), "model_state.pt")
```

### 실수 2. optimizer 상태를 저장하지 않는 경우

학습 재개가 목적이라면 optimizer 상태도 저장해야 합니다.

특히 Adam 같은 optimizer는 내부 상태를 사용하므로, optimizer 상태 없이 재개하면 이어서 학습하는 것과 달라질 수 있다.
