## 1. RNN/LSTM이 해결한 것

RNN은 순서가 있는 데이터를 처리할 수 있게 해주었다.

```
x1 → x2 → x3 → x4
```

그리고 LSTM은 RNN보다 오래 기억할 정보를 더 잘 유지할 수 있도록 cell state와 gate 구조를 사용했다.

| 모델 | 핵심 아이디어 |
| --- | --- |
| RNN | 이전 hidden state를 다음 시점으로 전달 |
| LSTM | cell state와 gate로 오래 기억할 정보 조절 |

## 3. 그래도 남는 한계

### 한계 1. 긴 문맥 처리의 어려움

LSTM은 RNN보다 장기 의존성 문제를 완화하지만, 아주 긴 문맥을 완벽하게 해결하는 것은 아니다

긴 문장이나 긴 문서에서는 중요한 정보가 매우 멀리 떨어져 있을 수 있다.<br>
이 경우 순서대로 정보를 전달하는 구조는 중간 과정을 많이 거쳐야 하므로 정보가 약해질 수 있다.

---

### 한계 2. 병렬 처리의 어려움

RNN/LSTM은 시점 순서대로 계산하는 구조다.

```
h1이 만들어져야 h2를 계산할 수 있고,
h2가 만들어져야 h3를 계산할 수 있다.
```

GPU는 많은 연산을 동시에 처리할 때 강력하다.<br>
하지만 RNN/LSTM은 시점 간 의존성이 강해서 sequence 길이가 길어질수록 병렬 처리 효율이 떨어질 수 있다.

## 4. Transformer로 이어지는 직관

RNN/LSTM의 핵심 제약은 한 시퀀스 안에서 앞 시점의 상태가 계산되어야 다음 시점을 계산할 수 있다는 점.

이후의 시퀀스 모델들은 이 순차 의존성을 줄이고 멀리 떨어진 위치의 정보를 다루는 다른 방법을 사용한다

## 5. 자주 하는 실수

### 실수 1. 새로운 구조가 있으니 RNN/LSTM은 몰라도 된다고 생각하기

hidden state, sequence length, padding, 마지막 유효 시점은 시퀀스 모델을 읽는 기본 개념이다.<br>
RNN/LSTM은 이 개념을 작은 코드로 확인하기 좋다.

### 실수 2. 모델 차이를 성능 숫자만으로 이해하기

RNN/LSTM은 상태를 시점 순서대로 전달한다.<br>
다른 구조와 비교할 때는 정확도뿐 아니라 입력 shape, 정보 전달 방식, 계산 순서와 실험 조건을 함께 본다
