학습 모드에서는 gradient를 계산하고, <br>
평가 모드에서는 `model.eval()`과 `torch.no_grad()`를 함께 사용해 안전하게 예측과 metric을 계산한다


## 2. 학습 코드와 평가 코드는 왜 다르게 작성하는지

학습 코드에서는 모델이 틀린 정도를 loss로 계산하고, 그 loss를 줄이기 위해 gradient를 계산해야 한다

```
학습: forward -> loss -> backward -> step
```

반면 평가 코드에서는 모델을 업데이트하지 않는다. validation loss나 accuracy만 확인한다.

```
평가: forward -> loss/metric 확인
```

따라서 평가에서는 gradient 계산이 필요 없다. 

gradient를 계산하지 않으면 메모리를 덜 쓰고 계산도 가벼워진다

다만 `model.eval()`이나 `torch.no_grad()` 자체가 파라미터를 영구적으로 동결하는 기능은 아니다.

실제 업데이트는 `backward()`와 `optimizer.step()`이 있을 때 일어난다.

## 3. `model.train()`과 `model.eval()`

`model.train()`과 `model.eval()`은 모델 내부 모듈의 동작 모드를 바꾼다

| 모드 | 사용 시점 | 의미 |
| --- | --- | --- |
| `model.train()` | 학습 단계 | Dropout, BatchNorm 등이 학습 모드로 동작 |
| `model.eval()` | 평가/추론 단계 | Dropout, BatchNorm 등이 평가 모드로 동작|

간단한 모델에서는 차이가 잘 보이지 않을 수 있지만, Dropout이나 BatchNorm이 들어가면 중요합니다.

```python
import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(4, 4),
    nn.ReLU(),
    nn.Dropout(p=0.5),
    nn.Linear(4, 2)
)

x = torch.ones(3, 4)

# 학습 모드에서는 Dropout이 활성화된다
model.train()
out_train_1 = model(x)
out_train_2 = model(x)

# 평가 모드에서는 Dropout이 비활성화된다
model.eval()
out_eval_1 = model(x)
out_eval_2 = model(x)

print("train outputs same?", torch.allclose(out_train_1, out_train_2))
print("eval outputs same?", torch.allclose(out_eval_1, out_eval_2))
```

`model.eval()`은 gradient 추적을 끄지 않아. gradient 추적을 끄려면 `torch.no_grad()`를 별도로 사용해야 한다.

## 4. `torch.no_grad()`가 필요한 이유

`torch.no_grad()`는 그 안에서 수행되는 연산에 대해 gradient 추적을 끈다

```python
import torch
import torch.nn as nn

model = nn.Linear(4, 2)
x = torch.randn(3, 4)

model.eval()

# eval 모드이지만 no_grad가 없으면 출력은 여전히 grad 추적 대상일 수 있습니다.
out = model(x)
print("without no_grad:", out.requires_grad)

# no_grad 안에서는 gradient 추적이 꺼집니다.
with torch.no_grad():
    out_no_grad = model(x)

print("with no_grad:", out_no_grad.requires_grad)
```

평가 코드에서는 보통 다음 패턴을 사용합니다.

```
[읽기용 코드 조각]
model.eval()

with torch.no_grad():
    pred = model(x)
    loss = criterion(pred, y)
```

`torch.no_grad()` 안에서 만든 loss는 `backward()`를 호출하는 학습용 loss가 아니다 평가용 loss 계산에 사용해야한다

## 5. `detach()`를 안전하게 사용하는 경우

`detach()`는 Tensor를 계산 그래프에서 분리한다

### 예시 1. 예측 결과를 NumPy로 변환하기

```python
model.eval()
with torch.no_grad():
    logits = model(x)

# CPU로 옮긴 뒤 NumPy 배열로 변환합니다.
logits_np = logits.detach().cpu().numpy()
print(type(logits_np))
```
### 예시 2. loss 값을 로깅하기

```
[읽기용 코드 조각]
loss_value = loss.detach().item()
print("loss value:", loss_value)
```

다만 학습 loss 계산 전에 예측값을 detach하면 안 됩니다.

```
[읽기용 코드 조각]
# 잘못된 예시입니다.
pred = model(x).detach()
loss = criterion(pred, y)

# 이 loss는 모델 파라미터와 연결되지 않을 수 있습니다.
```

## 6. 안전한 validation step 작성하기

이제 안전한 validation step을 함수로 작성

```python
def validation_step(model, criterion, x, y):
    """
    하나의 validation batch에 대해 loss를 계산합니다.
    평가에서는 파라미터를 업데이트하지 않으므로 no_grad를 사용합니다.
    """
    # 평가 모드로 전환합니다.
    model.eval()

    # gradient 추적을 끕니다.
    with torch.no_grad():
        pred = model(x)
        loss = criterion(pred, y)

    # 기록용 Python float로 반환합니다.
    return loss.item()
```

사용 예시

```python
model = nn.Linear(4, 2)
criterion = nn.CrossEntropyLoss()

x = torch.randn(8, 4)
y = torch.tensor([0, 1, 0, 1, 1, 0, 1, 0], dtype=torch.long)

valid_loss = validation_step(model, criterion, x, y)
print("valid_loss:", valid_loss)
```

## 7. Autograd 디버깅 체크리스트

| 확인 항목 | 확인 코드 |
| --- | --- |
| loss가 Tensor인가요? | `print(type(loss))` |
| loss가 scalar인가요? | `print(loss.shape, loss.ndim)` |
| backward를 호출했나요? | `loss.backward()` |
| gradient가 None인가요? | `print(param.grad is None)` |
| gradient shape가 맞나요? | `print(param.shape, param.grad.shape)` |
| no_grad 안에서 학습하고 있나요? | `with torch.no_grad()` 위치 확인 |
| detach를 너무 일찍 썼나요? | `.detach()` 위치 확인 |
| zero_grad를 호출했나요? | `optimizer.zero_grad()` |
| step을 호출했나요? | `optimizer.step()` |


loss가 `NaN`이나 무한대가 되거나 gradient가 폭주하면 먼저 유한한 값인지 확인해야한다

```
[읽기용 코드 조각]
if not torch.isfinite(loss):
    raise Runtime ㅜError(f"loss is not finite: {loss.item()}")

loss.backward()

for name, param in model.named_parameters():
    if param.grad is None:
        print(name, "gradient 없음")
        continue
    if not torch.isfinite(param.grad).all():
        raise RuntimeError(f"{name} gradient에 NaN/Inf가 있습니다.")
    print(name, "grad norm:", param.grad.norm().item())
```

원인을 찾기 어려울 때는 아래처럼 anomaly detection을 잠시 켤 수 있습니다.

```
[읽기용 코드 조각]
with torch.autograd.detect_anomaly():
    loss.backward()
```

이 기능은 계산이 느려지므로 상시 학습용이 아니라 디버깅할 때만 사용한다

## 8. 자주 하는 실수

### 실수 1. `model.eval()`만 쓰고 `torch.no_grad()`를 쓰지 않기

```python
model.eval()
pred = model(x)  # gradient 추적이 켜질 수 있습니다.
```

`model.eval()`은 모델을 평가 모드로 바꾸는 코드입니다.

즉, Dropout이나 BatchNorm처럼 학습 모드와 평가 모드에서 다르게 동작하는 layer의 동작 방식을 바꾼다

하지만 `model.eval()`만으로 gradient 계산이 꺼지는 것은 아니다

따라서 평가나 추론 단계에서 `torch.no_grad()`를 함께 사용하지 않으면,<br>
필요 없는 계산 그래프가 만들어져 메모리를 더 사용할 수 있다.


수정코드
```python
model.eval()
with torch.no_grad():
    pred = model(x)
```


### 실수 2. `torch.no_grad()` 안에서 학습하기

```python
# 잘못된 예시입니다.
with torch.no_grad():
    pred = model(x)
    loss = criterion(pred, y)

# 이 loss는 backward용으로 적절하지 않습니다.
# loss.backward()가 실패하거나 gradient가 흐르지 않을 수 있습니다.
```

`torch.no_grad()` 안에서는 PyTorch가 gradient 계산을 위한 기록을 남기지 않는다

그래서 이 안에서 만든 `loss`는 학습을 위한 `backward()`에 적절하지 않습니다.

학습 단계에서는 parameter를 업데이트하기 위해 gradient가 필요하다

따라서 학습 코드는 torch.no_grad() 밖에서 실행해야 한다

### 실수 3. validation 후 train 모드로 되돌리지 않기

학습 루프에서 validation을 수행한 뒤 다시 학습을 이어갈 때는 `model.train()`을 호출하면 된다

```python
# validation
model.eval()
with torch.no_grad():
    valid_pred = model(x)

# 다시 학습을 이어가기 전에 train 모드로 전환합니다.
model.train()
```

validation을 위해 `model.eval()`을 호출하면 모델은 평가 모드로 바뀐다

이 상태를 다시 `model.train()`으로 되돌리지 않으면, 이후 학습에서도 Dropout이나 BatchNorm이 평가 모드처럼 동작할 수 있습니다.

이 경우 코드가 오류를 내지 않을 수도 있어서 더 위험하다

겉으로는 학습이 진행되는 것처럼 보이지만, 일부 layer가 학습 모드로 동작하지 않아 의도한 학습 결과가 나오지 않을 수 있다.
