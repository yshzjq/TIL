# 1장 1강. 데이터 수집 방식 비교와 RAG 관점의 선택

## 1. 데이터 수집 전에 먼저 볼 것

데이터를 찾기 전에 **서비스가 어떤 질문에 답해야 하는지** 먼저 정해야 한다.

예를 들어:

- 현재 대여 가능한 자전거 수는? → **현재값 필요**
- 자전거 대여 규정은? → **설명과 문맥 필요**
- 지난달 이용량은? → **과거 데이터 필요**

질문을 볼 때 다음 3가지를 확인한다.

1. 값이 자주 바뀌는가?
2. 설명이나 앞뒤 문맥이 필요한가?
3. 과거 값과 비교해야 하는가?

---

## 2. 수집 경로와 데이터 형식

### 수집 경로

데이터를 **어디에서 어떤 방법으로 가져오는지**를 의미한다.

예:

- 파일 다운로드
- 공공데이터 API
- 외부 서비스 API
- 웹페이지 수집

### 데이터 형식

가져온 데이터가 **어떤 구조로 표현되는지**를 의미한다.

예:

- CSV: 행과 열로 이루어진 표
- JSON: 키와 값으로 이루어진 구조
- HTML: 웹페이지 구조
- PDF: 문서의 페이지 구조

### 핵심

> API와 JSON은 같은 종류의 개념이 아니다.

예를 들어:

```text
공공 API → JSON 응답
홈페이지 다운로드 → CSV 파일
```

따라서 다음 순서로 판단한다.

```text
어떤 경로로 가져올 것인가?
        ↓
어떤 형식으로 받을 것인가?
```

---

## 3. 주요 데이터 수집 방식

### 정적 파일

특정 시점의 데이터를 파일로 제공하는 방식이다.

예:

- CSV
- JSON
- PDF

장점:

- 보관하기 쉽다.
- 같은 데이터를 다시 사용할 수 있다.
- 많은 데이터를 한 번에 받기 좋다.

주의:

- 새 파일이 나오기 전까지 데이터가 갱신되지 않는다.

---

### 공공데이터 API

공공기관이 제공하는 API를 이용해 데이터를 조회한다.

장점:

- 날짜, 지역 등 필요한 조건만 조회할 수 있다.
- 자주 바뀌는 값을 조회하기 좋다.

주의:

- API Key가 필요할 수 있다.
- 호출 제한이 있을 수 있다.
- 데이터가 실제로 관측된 시각을 확인해야 한다.

---

### 외부 서비스 API

민간 서비스에서 제공하는 API이다.

예:

- 지도
- 번역
- 검색

장점:

- 직접 개발하기 어려운 기능을 쉽게 사용할 수 있다.

주의:

- 무료 사용량 제한
- 추가 비용
- 저장 정책
- 서비스 정책 변경

등을 확인해야 한다.

---

### 웹 데이터 수집

웹페이지의 HTML에서 필요한 데이터를 가져오는 방식이다.

장점:

- API나 파일로 제공되지 않는 내용을 얻을 수 있다.

주의:

- 웹페이지 구조가 바뀌면 코드가 깨질 수 있다.
- 광고나 메뉴 등이 데이터에 섞일 수 있다.
- `robots.txt`, 이용약관, 개인정보, 저작권을 확인해야 한다.

공식 API나 파일이 있다면 먼저 비교하는 것이 좋다.

---

## 4. 갱신 주기와 수집 비용

### 갱신 주기

데이터가 얼마나 자주 바뀌는지를 의미한다.

| 데이터 | 갱신 특징 | 적합한 방식 |
|---|---|---|
| 이용 규정 | 가끔 변경 | 문서 |
| 현재 대여 가능 수 | 자주 변경 | API |
| 월별 이용량 | 매월 변경 | 파일 / 스냅샷 |

데이터가 자주 변한다고 항상 API를 사용해야 하는 것은 아니다.

사용 목적에 맞는 갱신 주기를 선택해야 한다.

---

### 수집 비용

수집 비용에는 API 요금뿐만 아니라 다음도 포함된다.

- 데이터 정제 시간
- API 신청 및 관리
- 오류 대응
- 웹페이지 변경 대응
- 저장 공간과 백업
- 유지보수 시간

즉,

> 무료 API라고 해서 실제 운영 비용이 0원인 것은 아니다.

---

## 5. RAG, API, 스냅샷 선택

데이터의 성격에 따라 저장 방법을 다르게 선택한다.

### 공식 문서 + RAG

다음처럼 **설명과 문맥이 중요한 질문**에 적합하다.

- 신청 자격은?
- 취소 규정은?
- 용어의 의미는?

문서의 앞뒤 내용을 함께 저장하면 검색 결과의 의미를 이해하기 쉽다.

---

### 질문 시점 API

다음처럼 **현재값이 중요한 질문**에 적합하다.

- 지금 이용 가능한가?
- 오늘 미세먼지는?
- 현재 운영 중인가?

현재값은 저장된 RAG 문서보다 질문하는 순간 API로 조회하는 것이 적합하다.

---

### 주기적 스냅샷

스냅샷은 특정 시점의 API 응답이나 데이터를 저장하는 것이다.

다음과 같은 질문에 사용한다.

- 지난주와 이번 주 비교
- 하루 동안의 변화
- 지난달 평균

현재값 API가 과거 데이터를 제공한다고 가정하면 안 된다.

과거 분석이 필요하다면 데이터를 직접 저장해야 할 수 있다.

---

## 6. 가장 기본적인 선택 기준

데이터를 고를 때 다음 기준을 확인한다.

| 기준 | 확인 내용 |
|---|---|
| 목적 적합성 | 필요한 값이나 설명이 있는가? |
| 갱신성 | 필요한 시점의 데이터인가? |
| 구조 | 데이터 구조를 이해할 수 있는가? |
| 비용 | 운영 비용을 감당할 수 있는가? |
| 재현성 | 같은 원본을 다시 확인할 수 있는가? |
| 이용 가능성 | 저장·가공·사용 조건에 문제가 없는가? |

하나의 데이터 수집 방식만 사용할 필요는 없다.

예:

```text
규정 설명 → RAG 문서
현재 상태 → API
과거 분석 → 저장된 스냅샷
```

---

## 7. 출처와 메타데이터

데이터를 저장할 때 값만 저장하면 출처 정보가 사라질 수 있다.

따라서 다음과 같은 정보도 함께 저장하는 것이 좋다.

```text
source_url
creator
collected_at
updated_at
```

이러한 정보를 **메타데이터(metadata)**라고 한다.

메타데이터가 있으면 데이터의 출처와 수집 시점을 확인하기 쉽다.

## 8. Python으로 간단한 선택 규칙 만들기

질문의 특징을 딕셔너리로 표현할 수 있다.

```python
need = {
    "question": "현재 대여 가능한 자전거 수는?",
    "changes_often": True,
    "needs_explanation": False,
    "needs_history": False,
}
```

각 값의 의미:

```text
changes_often
→ 값이 자주 바뀌는가?

needs_explanation
→ 설명이나 문맥이 필요한가?

needs_history
→ 과거 데이터와 비교해야 하는가?
```

간단한 선택 규칙:

```python
def recommend_path(need):
    if need["needs_history"]:
        return "주기적 파일/스냅샷"

    if need["changes_often"]:
        return "질문 시점 API"

    if need["needs_explanation"]:
        return "공식 문서/RAG"

    return "정적 파일"
```

판단 흐름은 다음과 같다.

```text
과거 비교 필요?
    ↓ Yes
파일 / 스냅샷

No
↓
값이 자주 변함?
    ↓ Yes
질문 시점 API

No
↓
설명이 필요함?
    ↓ Yes
공식 문서 / RAG

No
↓
정적 파일
```

이 규칙은 절대적인 정답이 아니라 **첫 번째 후보를 고르는 기준**이다.

## 9. 자주 생기는 오해

### API가 항상 최신이다?

아니다.

API가 오래된 데이터를 제공할 수도 있으므로 데이터의 **기준 시각과 갱신 주기**를 확인해야 한다.

### 공공데이터는 항상 정확하다?

아니다.

공식 데이터도 다음 문제가 있을 수 있다.

- 데이터 누락
- 갱신 지연
- 필드 변경
- 오류

### RAG에는 모든 데이터를 넣어야 한다?

아니다.

빠르게 바뀌는 현재값은 RAG보다 API 조회가 더 적합하다.

### JSON이면 정제가 필요 없다?

아니다.

JSON도 다음 문제가 있을 수 있다.

- 값 누락
- 자료형 오류
- 중복
- 깊은 중첩 구조

---

## 10. 핵심 정리

```text
설명·규정·정의
→ 공식 문서 + RAG

현재 상태·실시간 값
→ 질문 시점 API

과거 비교·추세
→ 파일 또는 스냅샷
```

그리고 반드시 구분해야 한다.

```text
수집 경로
= 데이터를 가져오는 방법

데이터 형식
= 데이터를 표현하는 구조
```

예:

```text
API → 수집 경로
JSON → 데이터 형식
```

데이터 수집에서 가장 중요한 것은 최신 기술을 사용하는 것이 아니라,

> 사용자의 질문에 필요한 데이터를 가장 단순하고 안정적인 방법으로 가져오는 것이다.
