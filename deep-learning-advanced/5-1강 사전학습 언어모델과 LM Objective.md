## 1. 언어모델이란 무엇인가

**언어모델(Language Model)은 텍스트 안에서 토큰이 등장하는 패턴과 문맥 관계를 학습하는 모델이다.**

예를 들어 

```
오늘 날씨가 매우 ______.
```

빈칸에는 `좋다`, `춥다`, `덥다`처럼 문맥에 어울리는 표현이 들어갈 수 있다. <br>
언어모델은 대량의 텍스트를 보면서 다음과 같은 패턴을 학습한다

- 어떤 토큰이 함께 등장하는가?
- 어떤 순서가 자연스러운가?
- 앞뒤 문맥에 따라 같은 단어의 의미가 어떻게 달라지는가?
- 다음에 어떤 토큰이 이어질 가능성이 높은가?

> 언어모델이 문장을 사람처럼 “이해한다”고 단정하기보다,<br>
**학습 데이터에서 관찰한 토큰과 문맥의 통계적·구조적 패턴을 파라미터에 학습한다**고 표현하는 것이 더 정확하다.

## 2. 사전학습이 필요한 이유

텍스트 분류 모델을 처음부터 학습한다고 생각해 본다.<br>
우리가 가진 라벨 데이터가 5000개뿐이라면 모델은 다음을 동시에 배워야 한다.

1. 단어와 문장의 일반적인 의미
2. 문장 안의 관계
3. 우리 분류 문제의 라벨 기준

이 모든 것을 작은 데이터만으로 배우기는 어렵다.
<br>
그래서 먼저 대규모 비라벨 텍스트로 일반적인 언어 패턴을 학습한 뒤, 목적별 데이터에 적용한다

대규모 비라벨 텍스트란 사람이 정답 라벨을 붙이지 않은 대량의 일반 문장 데이터이며, 사전학습에서는 이 데이터를 이용해 모델이 언어의 의미와 문맥 패턴을 먼저 학습한다.

### 2-1. Pretraining

대규모 텍스트를 이용해 일반적인 언어 패턴을 학습하는 단계

```
대규모 비라벨 텍스트
-> LM Objective 수행
-> 일반 언어 패턴을 가진 사전학습 모델
```

### 2-2. Task 적용

사전학습 모델을 실제 문제에 연결하는 단계

- Fine-tuning: 목적별 데이터로 모델 파라미터를 추가 학습<br>사전학습된 모델을 내 데이터로 다시 조금 더 학습시키는 것
    
- Task Head 추가: 분류기처럼 문제에 맞는 출력 계층을 붙인다.<br>
Task Head = 내가 풀고 싶은 문제에 맞는 마지막 출력층


- Feature 활용: 사전학습 모델의 표현을 다른 모델의 입력으로 사용한다.
- Prompt 기반 사용: 생성 모델에 지시문과 예시를 제공해 바로 사용한다

## 3. LM Objective란 무엇인가


Objective는 모델이 학습 중 반복해서 풀도록 설계한 문제로, 모델의 학습 목표와 방향을 정한다.

즉, 모델에게

어떤 입력을 줄지

무엇을 정답으로 삼을지

어떤 문맥을 볼 수 있게 할지

어느 출력에 loss를 계산할지

를 정해서, 그 문제의 loss를 줄이는 방향으로 모델이 학습되도록 합니다.


예를 들어:

BERT  → 문장의 일부를 가리고 원래 토큰을 맞히기
GPT   → 이전 토큰을 보고 다음 토큰을 맞히기

따라서 간단히 기억하면:

Objective = 모델이 학습할 때 계속 풀게 되는 문제 유형
          = 무엇을 잘하도록 학습할지 정하는 규칙

이 차이는 모델이 자연스럽게 사용하는 문맥 방향과 기본 활용 방식에 영향을 준다

" loading="lazy">

Objective가 모델 행동에 미치는 영향

> 모델의 능력을 Objective 하나로만 결정할 수는 없다.<br>
>구조, 데이터 규모와 품질, Tokenizer, 모델 크기, Fine-tuning 방식도 함께 영향을 준다

## 4. Masked LM과 Causal LM 맛보기

### 4-1. Masked Language Modeling

문장 일부를 가리고 원래 토큰을 맞히게 한다
```
원문: Paris is the capital of France.
입력: Paris is the [MASK] of France.
정답: capital
```

특징:

- 가려진 위치의 왼쪽과 오른쪽 문맥을 함께 볼 수 있다.
- 문장 전체의 관계를 반영한 표현을 학습하기 좋다.
- BERT가 대표적인 Masked Language Model다.

### 4-2. Causal Language Modeling

Causal = 미래를 미리 보지 않고, 지금까지 나온 내용만 보고 다음을 예측하는 방식

이전 토큰으로 다음 토큰을 맞히게 한다

```
입력: AI can
정답: help

입력: AI can help
정답: people
```

특징:

- 각 위치에서 미래 토큰을 볼 수 없다.
- 다음 토큰 예측을 반복하면 새 텍스트를 생성할 수 있다.
- GPT 계열이 대표적인 Causal Language Model다.

| 비교 항목 | Masked LM | Causal LM |
| --- | --- | --- |
| 대표 질문 | 가려진 토큰은 무엇인가? | 다음 토큰은 무엇인가? |
| 문맥 방향 | 왼쪽 + 오른쪽 | 왼쪽 + 현재 |
| 대표 모델 | BERT | GPT |
| 자연스러운 출발점 | 문맥 표현, 분류, 토큰 이해 | 이어쓰기, 생성, 대화 |

## 선택 · 5. Representation Learning과 Generation Learning

### 5-1. Representation Learning

Representation은 모델 내부에서 사용하는 **문맥 표현 벡터**다.

예를 들어 `은행`이라는 단어는 다음 문장에서 의미가 다르다

```
은행에서 계좌를 만들었다.
강가에 은행나무가 있었다.
```

Encoder-only 모델은 각 토큰이 문장 전체를 참고하도록 만들어 `은행`의 표현을 문맥에 맞게 바꾼다

- 문장 분류
- 토큰 분류
- 검색 임베딩
- 유사도 계산
- 질의응답용 문맥 표현

### 5-2. Generation Learning

Generation은 이미 주어진 문맥 뒤에 올 토큰을 순차적으로 예측하는 과정

```
Prompt: 인공지능은 교육에서
Continuation: 개인별 학습 자료를 만드는 데 활용될 수 있습니다.
```

이 방식은 다음 작업에 자연스럽게 이어진다

- 문장 이어쓰기
- 대화
- 요약 결과 생성
- 코드 생성
- 형식화된 응답 생성

> Representation Learning과 Generation Learning은 완전히 분리된 세계가 아니다.
>생성 모델도 내부 표현을 만들고, Encoder 모델도 Task Head와 Fine-tuning을 통해 다양한 출력을 만들 수 있다. 여기서는 **기본 Objective가 직접 연습시키는 행동**을 비교한다.



## 6. Downstream Task란 무엇인가

Downstream Task는 사전학습 모델을 실제 목적에 적용하는 구체적인 문제다.

| Downstream Task | 입력 | 출력 | 자연스러운 모델 후보 |
| --- | --- | --- | --- |
| 고객 문의 intent 분류 | 문의 문장 | 클래스 라벨 | Encoder-only + Classification Head |
| 개인정보 토큰 탐지 | 문장 | 토큰별 라벨 | Encoder-only + Token Classification Head |
| 문서 검색 | 질의·문서 | 임베딩·유사도 | Encoder 계열 임베딩 모델 |
| 답변 초안 생성 | 질문·문맥 | 새 텍스트 | Decoder-only 또는 Encoder-Decoder |
| 번역 | 원문 | 번역문 | Encoder-Decoder |

여기서 자연스러운 후보는 절대 규칙이 아닙니다. 실제 선택에서는 다음도 확인해야 한다.

- 모델이 지원하는 언어
- 학습 데이터와 도메인
- Model card와 라이선스
- 파라미터 수와 VRAM
- 지연시간과 비용
- 실제 평가 데이터 성능


## 7. 구조와 Objective를 함께 봐야 하는 이유

문제 → 필요한 출력과 문맥 파악 → 적합한 구조 선택 → Objective와 용도 확인 → 최종 모델 선택

**문제를 파악하고 맞는 모델을 선택**

구조와 Objective를 같은 개념으로 외우면 새로운 모델을 만났을 때 혼란이 생긴다.<br>
이후에는 Model card에서 architecture, pretraining objective, intended use를 따로 확인하세요.

Model Card에서 구조, 사전학습 방식, 권장 사용 목적을 각각 확인해서 모델의 성격과 용도를 판단하라는 뜻

## 이해도 점검

1. 언어모델은 어떤 패턴을 학습하나?
2. 사전학습과 Fine-tuning의 차이는 무엇인가
3. LM Objective를 한 문장으로 설명
4. Masked LM과 Causal LM의 대표 학습 질문은 각각 무엇인가
5. 구조와 Objective를 따로 봐야 하는 이유는 무엇인가
6. 생성 태스크에서 Decoder-only가 자연스러운 출발점이 되는 이유는 무엇인가

### 정답 확인

1. 토큰의 등장 순서, 함께 등장하는 관계, 문맥에 따른 의미 변화 등을 학습합니다.
2. 사전학습은 대규모 데이터에서 일반 패턴을 익히는 단계이고, Fine-tuning은 더 작은 목적별 데이터로 모델을 문제에 맞게 추가 학습하는 단계다.
3. 모델이 사전학습 중 반복해서 풀도록 설계한 문제입니다.
4. Masked LM은 가려진 토큰 예측, Causal LM은 이전 토큰을 바탕으로 다음 토큰 예측입니다.
5. 같은 구조라도 다른 Objective를 사용할 수 있고, 구조는 정보 흐름을, Objective는 학습 문제를 설명하기 때문입니다.
6. 이전 토큰으로 다음 토큰을 예측하는 학습 방식이 새 텍스트를 순차적으로 만드는 과정과 직접 연결되기 때문이다

## 요약

- 언어모델은 텍스트의 토큰·순서·문맥 패턴을 학습한다
- 사전학습은 대규모 비라벨 데이터에서 재사용 가능한 언어 패턴을 학습하는 단계다
- LM Objective는 모델이 사전학습 중 반복해서 푸는 문제다.
- Masked LM은 가려진 토큰을 양쪽 문맥으로 예측하고, Causal LM은 왼쪽 문맥으로 다음 토큰을 예측한다
- BERT와 GPT는 구조와 Objective 조합이 다르며, 문제의 입력·출력·문맥 방향을 보고 후보를 선택해야 한다
