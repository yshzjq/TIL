## 1. 왜 토큰끼리 서로 참고해야 할까

Tokenizer는 문장을 토큰으로 나누고 각 토큰을 ID로 바꾼다.<br>
하지만 **토큰 ID만으로는 문맥에 맞는 의미가 완성되지 않는다.**


```
문장 A: 강아지는 공을 쫓지 않았습니다. 그것이 너무 피곤했기 때문입니다.
문장 B: 강아지는 공을 쫓지 않았습니다. 그것이 너무 멀리 있었기 때문입니다.
```

문장 A의 그것은 강아지를 가리키고, 문장 B의 그것은 공을 가리키는 것이 자연스럽습니다.<br>
같은 토큰이라도 주변 문맥에 따라 참고해야 할 대상이 달라진다

### 1-1. 토큰의 기본 표현과 문맥 표현

처음 임베딩된 토큰 표현에는 그 토큰의 기본적인 의미가 있다

self-Attention을 통과하면 주변 토큰과의 관계가 반영된 문맥 표현(contextual representation)으로 바뀐다

```
기본 토큰 표현
    + 주변 토큰과의 관계
    = 문맥이 반영된 새로운 토큰 표현
```

Self-Attention은 토큰을 새로운 ID로 바꾸는 과정이 아니고<br>
기존 토큰 표현을 **문맥에 맞게 업데이트하는 과정**이다.

## 2. Attention은 무엇을 하는 방식인가

현재 토큰이 다른 토큰들을 살펴보고, 필요한 정보를 서로 다른 비율로 가져오는 방식

## 3. Query, Key, Value를 정보 찾기로 이해

| 역할 | 쉬운 질문 | 정보 찾기 비유 |
| --- | --- | --- |
| Query | 지금 무엇을 알고 싶은가요? | 검색 질문 |
| Key | 이 후보는 질문과 어떤 관련이 있나요? | 검색 색인·분류표 |
| Value | 이 후보에서 실제로 가져올 정보는 무엇인가요? | 검색 결과 내용 |

### 3-1. Query: 지금 필요한 정보

Query는 현재 토큰이 다른 토큰에게 던지는 질문과 비슷하다

```
"먹었다"의 Query
-> 누가 먹었는가?
-> 무엇을 먹었는가?
-> 어디에서 먹었는가?
```

Query가 실제 한국어 문장으로 저장된다는 뜻은 아니다.<br>

### 3-2. Key: 비교할 때 사용하는 특징

각 후보 토큰의 Key는 Query와 비교할 때 사용

```
민수는   -> 행동의 주체와 관련된 특징
식당에서 -> 장소와 관련된 특징
라면을   -> 행동의 대상과 관련된 특징
```

Query와 Key를 비교한 결과가 **관련도 점수(score)**다. 

### 3-3. Value: 실제로 가져올 내용

Value는 어떤 위치를 참고하기로 결정한 뒤, 그 위치에서 실제로 가져오는 정보입니다.

```
"민수는"의 Value -> 사람·주체 관련 정보
"식당에서"의 Value -> 장소 관련 정보
"라면을"의 Value -> 음식·대상 관련 정보
```

Key는 "얼마나 참고할지"를 정할 때 사용하고, Value는 "무엇을 가져올지"에 사용한다

## 4. 문장 예제로 Q/K/V 역할 읽기

문장 예제의 Q/K/V 역할

| 후보 토큰 | Key로 비교할 때 기대하는 관계 | Value에서 가져올 수 있는 정보 |
| --- | --- | --- |
| 민수는 | 누가 먹었는가? | 행동의 주체가 민수라는 정보 |
| 식당에서 | 어디에서 먹었는가? | 행동이 일어난 장소가 식당이라는 정보 |
| 매운 | 어떤 라면인가? | 대상의 속성이 맵다는 정보 |
| 라면을 | 무엇을 먹었는가? | 행동의 대상이 라면이라는 정보 |
| 먹었다 | 현재 Query 자신과 어떤 관계인가? | 문장의 중심 행동 정보 |

핵심은 **후보 토큰이 Query와 어떤 관계인지**, 그리고 **그 위치에서 어떤 내용을 가져올 수 있는지**를 설명하는 것입니다.

## 5. Self-Attention에서 Q/K/V는 어디에서 나오나

Self-Attention의 self는 Q, K, V가 동일한 입력 시퀀스 X에서 만들어진다는 의미.<br>
같은 입력에서 출발하지만 서로 다른 Linear projection을 거치므로 Q, K, V의 값과 역할은 서로 다르다.

```
입력 토큰 표현 X
├─ 질문 역할로 변환 -> Q
├─ 비교 기준 역할로 변환 -> K
└─ 가져올 내용 역할로 변환 -> V
```

Q, K, V는 모두 같은 입력 X에서 출발하지만, 각각 서로 다른 nn.Linear를 통과하기 때문에 서로 다른 역할에 맞는 벡터가 만들어진다.

X → Q용 Linear → "무엇을 찾을지" 표현
X → K용 Linear → "비교할 기준" 표현
X → V용 Linear → "실제로 전달할 정보" 표현

### 5-1. 선택 학습: Shape만 코드로 확인

```python
import torch
from torch import nn

# 예시 입력의 크기를 정합니다.
# B=2: 문장 두 개를 한 번에 처리합니다.
# L=5: 각 문장을 토큰 길이 5로 맞췄다고 가정합니다.
# D=8: 각 토큰을 8개의 숫자로 표현한다고 가정합니다.
B, L, D = 2, 5, 8

# x는 토큰의 현재 표현입니다.
# shape은 [배치, 토큰 길이, 표현 차원] = [B, L, D]입니다.
x = torch.randn(B, L, D)

# Q, K, V를 만들기 위한 서로 다른 선형 계층입니다.
# 세 계층 모두 입력과 출력 차원은 D로 같지만, 학습되는 가중치는 서로 다릅니다.
to_q = nn.Linear(D, D, bias=False)
to_k = nn.Linear(D, D, bias=False)
to_v = nn.Linear(D, D, bias=False)

# 같은 x에서 출발하지만 서로 다른 선형 계층을 통과합니다.
q = to_q(x)
k = to_k(x)
v = to_v(x)

# 선형 계층은 마지막 차원 D만 변환하므로 B와 L은 유지됩니다.
print("x shape:", x.shape)
print("q shape:", q.shape)
print("k shape:", k.shape)
print("v shape:", v.shape)

# Q, K, V는 모두 [B, L, D] shape인지 확인합니다.
assert q.shape == (B, L, D)
assert k.shape == (B, L, D)
assert v.shape == (B, L, D)
```

### Projection이란 무엇인가

Projection은 여기서는 입력 벡터를 다른 역할의 벡터로 바꾸는 선형변환
<br>+ 같은 토큰 표현을 목적에 맞는 새로운 표현으로 변환하는 것

## 6. 연습 문제: Q/K/V 역할표 

| 후보 토큰 | Key로 비교할 때 기대하는 관계 | Value에서 가져올 수 있는 정보 |
| --- | --- | --- |
| 지수는 | 누가 읽었는가? | 읽은 사람은 지수라는 정보 |
| 도서관에서 | 어디에서 읽었는가? | 읽은 장소는 도서관이라는 정보 |
| 새로운 | 어떤 책인가? | 책이 새롭다는 속성 정보 |
| 인공지능 | 어떤 주제의 책인가? | 책의 주제가 인공지능이라는 정보 |
| 책을 | 무엇을 읽었는가? | 읽은 대상은 책이라는 정보 |

### 정답

1. 현재 토큰이 다른 토큰과의 관계를 참고해 문맥에 맞는 표현을 만들기 위해 필요합니다.
2. Query는 질문, Key는 비교 기준, Value는 실제로 가져올 정보입니다.
3. Key는 관련도를 계산하는 데 사용하고, Value는 관련도에 따라 실제 출력에 섞입니다.
4. 같은 입력 토큰 표현에서 서로 다른 학습 가능한 변환을 통해 만들어집니다.
