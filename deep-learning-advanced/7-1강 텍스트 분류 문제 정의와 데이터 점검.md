## 1. 텍스트 분류 문제를 먼저 정의해야 하는 이유

텍스트 분류 Fine-tuning은 모델을 불러와서 학습 버튼을 누르는 작업이 아니다. 

먼저 **무엇을 입력으로 받고, 어떤 라벨을 예측하며, 어떤 기준으로 성공을 판단할지** 정해야 한다. 

이 정의가 흔들리면 학습 결과가 좋아 보여도 실제 문제 해결과 연결되지 않을 수 있다.

모델 성능이 낮을 때 원인은 모델 구조가 아니라 **문제 정의, 라벨 품질, split 정책, metric 선택**에 있을 수 있다

## 2. 문제 정의 5요소


| 항목 | 질문 | 예시 |
| --- | --- | --- |
| 입력 | 모델이 읽는 텍스트는 무엇인가요? | 뉴스 제목, 리뷰, 고객 문의 |
| 출력 | 모델이 예측해야 하는 것은 무엇인가요? | topic, sentiment, intent |
| 라벨 규칙 | 각 라벨은 어떤 의미인가요? | `sports`는 스포츠 기사 제목 |
| 성공 기준 | 어떤 metric을 중요하게 볼까요? | Macro-F1, Accuracy, 클래스별 Recall |
| 실패 리스크 | 모델이 틀리면 어떤 문제가 생기나요? | 잘못된 라우팅, 민감 문의 누락 |


Fine-tuning을 할수록 코드가 복잡해 보이지만, 결국 “입력 문장 하나가 어떤 라벨로 가야 하는가?”를 배우는 과정이다.

코드를 보기 전에 문제 정의를 먼저 읽는 습관이 중요하다

## 선택 · 4. Label schema와 imbalance 점검

Label schema는 모델이 예측할 수 있는 라벨 목록과 의미다.

모델은 `정치`, `경제` 같은 단어 자체를 예측하는 것이 아니라 정수 id를 예측한다<br>
따라서 사람이 읽는 라벨 이름과 모델 출력 id를 연결하는 매핑이 필요하다

라벨 불균형 이해

```python
# ============================================================
# Label schema 확인
# ============================================================
# Datasets의 features에는 컬럼별 자료형과 메타데이터가 들어 있습니다.
# label 컬럼이 ClassLabel 형식이면 .names에서 사람이 읽을 수 있는 라벨 이름을 얻을 수 있습니다.
label_feature = raw_ds["train"].features[LABEL_COL]
label_names = label_feature.names
num_labels = len(label_names)

# id2label: 모델 출력 index -> 사람이 읽는 라벨 이름
# label2id: 사람이 읽는 라벨 이름 -> 모델 학습용 정수 id
id2label = {i: name for i, name in enumerate(label_names)}
label2id = {name: i for i, name in id2label.items()}

print("label_names:", label_names)
print("num_labels:", num_labels)
print("id2label:", id2label)
print("label2id:", label2id)

# ============================================================
# Label imbalance 확인
# ============================================================
# train split의 label id 목록을 pandas Series로 바꾼 뒤, label별 샘플 수를 계산합니다.
train_label_counts = pd.Series(raw_ds["train"][LABEL_COL]).value_counts().sort_index()

label_report = pd.DataFrame({
    "label_id": train_label_counts.index,
    "label_name": [id2label[i] for i in train_label_counts.index],
    "count": train_label_counts.values,
})

# ratio는 전체 train 데이터 중 해당 라벨이 차지하는 비율입니다.
# ratio가 매우 낮은 라벨은 모델이 충분히 학습하지 못할 수 있습니다.
label_report["ratio"] = label_report["count"] / label_report["count"].sum()
display(label_report)
```

### 코드 해설

`id2label`과 `label2id`는 추론 결과 해석에 꼭 필요하다

예를 들어 모델이 `3`을 예측했다면 사람이 바로 의미를 알기 어렵다. 그래서 `id2label[3]`을 통해 라벨 이름으로 바꿔야 합니다.

또한 라벨 분포가 심하게 불균형하면 Accuracy만으로 모델을 평가하기 어렵다.<br>
대부분의 샘플이 특정 라벨에 몰려 있다면, 모델이 그 라벨만 많이 예측해도 Accuracy가 높아질 수 있다.

## 5. 결측·중복·data leakage 후보 점검

데이터 품질 점검은 모델 성능을 높이기 위한 전처리 체크리스트다. 

결측이 있으면 학습 중 오류가 날 수 있고, 중복이 split을 넘어 섞이면 평가 성능이 실제보다 높게 나올 수 있다.

데이터 품질 점검 체크리스트

```python
# ============================================================
# DataFrame으로 변환해 품질 점검
# ============================================================
# Dataset.to_pandas()는 Dataset을 pandas DataFrame으로 변환합니다.
# 큰 데이터셋에서는 메모리를 많이 사용할 수 있으므로 샘플링해서 점검할 수도 있습니다.
train_df = raw_ds["train"].to_pandas()

# 1) 결측 확인
# title이나 label이 비어 있으면 학습 전 제거하거나 원인을 확인해야 합니다.
missing_report = train_df[[TEXT_COL, LABEL_COL]].isna().sum()
print("결측 개수:")
print(missing_report)

# 2) 중복 title 확인
# 같은 title이 여러 번 등장하면 train/valid/test 분할 시 leakage 후보가 될 수 있습니다.
duplicate_count = train_df.duplicated(subset=[TEXT_COL]).sum()
print("중복 title 수:", duplicate_count)

# 3) 라벨 이름이 입력 title에 직접 들어 있는지 단순 규칙으로 확인합니다.
# 실제 프로젝트에서는 더 정교한 leakage 규칙을 정의해야 합니다.
leakage_candidates = []
for row in train_df[[TEXT_COL, LABEL_COL]].head(2000).itertuples(index=False):
    text = getattr(row, TEXT_COL)
    label_id = getattr(row, LABEL_COL)
    label_name = id2label[label_id]
    if isinstance(text, str) and label_name.lower() in text.lower():
        leakage_candidates.append((text, label_name))

print("단순 leakage 후보 수:", len(leakage_candidates))
print("후보 예시:", leakage_candidates[:5])
```

```
단순 leakage 후보 수: 22

```

### 코드 해설

이 코드는 완벽한 leakage 탐지기가 아니다.

“정답 라벨이 입력에 직접 포함되어 있는가?” 같은 단순 규칙부터 확인하는 습관을 만들기 위한 예시다.

실제 프로젝트에서는 데이터 생성 과정, 파일명, 메타데이터, 중복 문서, 시간순 분할 여부까지 함께 점검해야 합니다.

## 7. 정답 확인

1. 예시 답안입니다. 고객 문의 intent 분류라면 입력은 고객 문의 문장, 출력은 `배송`, `환불`, `결제`, `계정` 같은 intent label, 라벨 규칙은 각 intent의 포함/제외 기준, 성공 기준은 Macro-F1과 소수 클래스 Recall, 실패 리스크는 중요한 환불·계정 문의를 놓치는 것이다.
2. `id2label`은 모델 출력 정수 id를 사람이 읽는 라벨 이름으로 바꾸기 위해 필요합니다. `label2id`는 사람이 정의한 라벨 이름을 모델 학습에 사용할 정수 id로 바꾸기 위해 필요하다
3. 불균형 데이터에서는 모델이 다수 클래스만 많이 맞혀도 Accuracy가 높게 나올 수 있습니다. 따라서 소수 클래스 성능이 나쁜데도 전체 성능이 좋아 보일 수 있다.
4. 예시 답안입니다. 같은 문장이 train과 validation에 동시에 존재하는 경우, 입력 문장에 정답 라벨명이 직접 들어 있는 경우, 파일명이나 메타데이터에 정답 정보가 들어 있는 경우, 시간순으로 예측해야 하는 문제인데 미래 데이터를 학습에 사용한 경우가 leakage 후보다.

## 8. 이번 강의 요약

텍스트 분류 Fine-tuning은 문제 정의에서 시작합니다. 입력, 출력, 라벨 규칙, 성공 기준, 실패 리스크를 먼저 정리해야 한다

데이터셋을 불러온 뒤에는 컬럼, 라벨 매핑, 라벨 분포, 결측, 중복, leakage 후보를 확인한다.
