# KANT_프로젝트_1차(2일차)

첫날에 만든 **Slack 자료 기반 LLM 교육 안내 도우미**를 이어서 개발했다. 오늘은 여러 질문을 한 번에 실행하고 결과를 기록하는 기능을 추가했으며, 평가 질문과 품질 기준을 정해 두 로컬 모델의 품질과 성능을 1차로 비교했다.

## 단계별 진행 상황

1. **[STEP 4. 모델 실행 환경 확인과 Python 연결] — 진행 중**  
   Python과 Ollama 모델 실행 준비를 마쳤다. 프로그램을 실행하면 약 10개 이상의 질문을 연속으로 보내고, 각 답변과 응답 시간을 함께 기록하는 평가 모드를 추가했다. 원하는 답변을 얻기 위한 프롬프트는 평가 결과에 따라 계속 수정할 예정이다.

   Slack API를 통해 기존 대화 기록을 가져오고, 새 글이나 수정된 글을 감지해 데이터를 갱신하는 구조도 만들고 있다. 데이터가 많아졌을 때 모든 내용을 프롬프트에 직접 넣어도 되는지, 검색이나 RAG와 같은 더 효율적인 방법이 있는지도 계속 살펴보고 있다.

2. **[STEP 5. 평가 질문과 품질 기준 확정] — 진행 중**  
   정상 질문, 경계가 모호한 질문, 정보가 부족한 질문, 서비스 범위를 벗어난 질문 등 네 가지 유형으로 평가 질문 18개를 준비했다.

   답변은 다음 다섯 항목을 각각 0~2점으로 평가했다.

   - **정확성**: 답변이 Slack 기록과 일치하는가
   - **핵심 정보 포함**: 답변에 필요한 핵심 내용이 빠짐없이 들어 있는가
   - **지시·형식 준수**: 질문의 의도와 요구한 형식에 맞게 답했는가
   - **한국어 표현**: 문장이 자연스럽고 이해하기 쉬운가
   - **정보 부족 시 대응**: 근거가 없을 때 사실을 만들어내지 않고 정보가 부족하다고 안내하는가

3. **[STEP 6. 로컬 모델 품질·성능 측정] — 1차 완료**  
   `qwen3:4b-instruct-2507-q4_K_M`과 `exaone3.5:7.8b`를 대상으로 16개 질문의 답변과 응답 시간을 비교 문서에 정리했다. 측정 결과 평균 응답 시간은 Qwen3가 약 1.77초, EXAONE이 약 2.32초로 Qwen3가 더 빨랐다.

   두 모델 모두 일반적인 안내 질문과 정보 부족 질문에는 대체로 잘 답했다. 다만 Qwen3는 코드 오류·환경 설정 질문에서 관련 없는 답변을 생성했고, 두 모델 모두 당일 제출 항목이나 Cursor 사용 가능 여부처럼 기록의 시점과 근거를 정확히 구분해야 하는 질문에서는 개선이 필요했다. 현재 결과는 프롬프트와 검색 방식 개선을 위한 1차 기준으로 활용할 예정이다.
